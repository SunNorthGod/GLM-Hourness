# GLM-Hourness 项目宪章

版本：0.2（2026-10-27）。本版取代 `C:\Users\29596\Desktop\Project\dsh-glm-dialect\docs\00-charter.md`（v0.1）；01/02 系列参考文档仍在原址，迁移至本目录为后续待办。
命名：**GLM-Hourness** = GLM + House + Harness。GLM 说要盖新房子，Harness 工程是房子的承重结构。工作名 dsh-glm-dialect 废弃。

## 1. 项目目标（四轴，缺一不可）

1. **无损**：GLM 以官方 ZCode 训练分布接入 DSH——模型质量与官方一致，不为照顾 harness 裁剪。
2. **治顽疾**：借重写接入层的机会修复 ZCode 已知痛点（MCP schema 行李、上下文膨胀、记忆陈旧无清理），做得比 ZCode 更好。
3. **自由度**：完全遵守 DSH 开放、万物皆插件的生态——每个能力独立插件行、可单独禁用、失败 fail-open、不污染其他 provider。
4. **工程美学**：代码洁癖、强迫症、优雅、极简（Go 式）作为设计轴而非口号——概念少、默认即用、配置面小、命名一致、零死代码零冗余路径；每次提交都过美学审查。

本项目是 harness 调校工程，不是代码任务：核心是塑造模型行为（告知 → 拦截 → 纠偏 → 申报 → 记忆化的闭环），度量是行为质量的持续改善。

## 2. 度量（产品层面，明确非字节级）

- 字节级 diff 不是验收标准，只作 transport 层调试工具。
- 验收度量：模型行为质量（长任务完成率、todo 纪律、指令遵循）、无损性（用户体感与官方无差）、顽疾修复（token 效率、上下文卫生、调校曲线——每会话违规次数随调校积累下降）、DSH 生态融合度（可组合、可退化）。
- 「和 DSH 一样」「和 ZCode 一样」均不构成达标条件；长期优化是常态。

## 3. 知识与文件组织

**LLM 的家 = 工作区 `.llm/`**，LLM 的一切私产落在这里：

```
.llm/
├── docs/     # harness 设计文档、外部事实账、digest
├── memory/   # 记忆库（MEMORY.md 索引 + 单条事实文件）
└── audit/    # guard 审计日志（出界申报、批准记录、违规统计）
```

**项目知识库 ≠ `.llm/`**：面向干活的知识（流程图、架构选型及理由、git 复现的修改历史、待办、文字版端到端测试案例库五件套）跟组件住（组件目录内），不集中放置——检索效率面向 AI，不面向人类目录审美（Law of Knowledge Decay，来源：原子能实践记录）。改代码必须同步更新对应组件知识库（workflow 完成门禁之一）；运维态定时全项目巡检。

**个人层**：只有人设进用户全局 AGENTS.md，不进社区插件。其余习惯（汇报三段式、许愿式视角、中文风格、工程洁癖、文档标准）全部产品化为插件默认文案与 skill。

## 4. 行为调校原则

- **违规硬拒，不做软放行**：放行即负强化（模型看到「这样做也能成」会重复）。拒绝必附纠偏四段式：事实（做了什么）/越界（违反哪条）/正路（应该怎么做）/例外（需要出界走申报）。
- **申报协议**：出界操作必须结构化申报——去哪里、做什么、危险性自查（可逆性/爆炸半径）、是否自查过替代方案；次次人批，批准只放行当次，不产生任何残留授权（无会话白名单）。
- **文件修改只用专用工具**（Write/Edit 族）；用 shell 改文件一律拒绝 + 纠偏。shell 合法用途 = 执行（测试/构建/git 操作）。
- **提示词写意图不写穷举**：harness 镜像层逐字照抄 ZCode 原文（训练分布）；自写节（guard 告知、workflow 准则、纠偏模板）只写意图与边界 + 少量示例，留足自由发挥空间。
- **skill 遵守力不托底硬规矩**：硬约束由插件在执行边界强制；skill 只承载流程知识，靠强触发描述 + 常驻目录节 + 状态机推送三重提高命中率，遵守率纳入审计。
- **用户习惯画像**：每次调校信号（五键卡片点按、纠偏、拒绝理由、汇报细度反馈）自动沉淀为 `.llm/memory/` 的 feedback/user 类记忆（含 Why/How to apply），下会话开局召回注入——习惯贴近靠累积的画像，不靠每次重新教。度量：同类纠正的重复率随时间下降。
- **度量把控**：四轴各有硬指标——无损（双臂探针完成率/纪律对齐）、治顽疾（token 效率、记忆信噪比）、自由度（启停矩阵零污染）、美学（死代码扫描归零、命名一致性检查、配置面行数、重复段落归零）+ 调校（违规率曲线、纠正重复率、待批队列积压）。不设「和谁一样」的达标线，只看曲线走向。

## 5. 文档管理五条量化标准

1. 单一事实源：每个事实只活在一处，引用不复制；审计扫描重复段落归零。
2. 可追溯：定案带日期 + 证据来源（偏移/抓包/实测/决议）；被推翻的定案整条重写或删除，不叠补丁。
3. 时效：文档与行为改动同一批落盘；每份文档带版本 + 日期头；过期文档入清理清单。
4. 可导航：`.llm/docs/` 有索引；孤儿文档（无入链）归零。
5. 生命周期：生效/历史/已废除三态，废除即删文件。

## 6. 形态

DSH bundle：**单一 npm 包**（如 `dsh-glm-hourness`），包内七个插件行（多插件一包，cordis.patch.yml 列出）——不拆多包发布，无命名冲突问题；模型无关行不加 glm 前缀：

| 行 | 职责 | 轴 |
|---|---|---|
| dsh-glm-llm | transport：身份头/签名/端点路由/凭据管理/模型目录/thinking 组装/beta 头 | 无损 |
| dsh-glm-prompt | content：提示词镜像/工具投影/todo 提醒回路/compact 镜像 | 无损 |
| dsh-toolsearch | 机制：deferred 懒加载 + ToolSearch | 治顽疾 |
| dsh-memory | 机制：`.llm/memory/` 记忆体系 + 卫生审计（不与 ZCode 共享） | 无损+治顽疾 |
| dsh-guard | 机制：规矩数据框架（告知/探测/纠偏/申报/审计）+ 文件圈禁 | 调校 |
| dsh-workflow | 机制：规划循环 → 多模型子代理并行派发 → 测试门禁 → 运维巡检 | 调校+multitask |
| dsh-hourness-ui | client 插件：分屏多项目/派遣面板/峰谷指示/问答审批卡片 | 体验 |

设计美学：极简（Go 式）——概念少、默认即用、配置面小、每个行为可关；不留「以防万一」的机构和参数。

内容改写只走构建层（systemPrompt / 工具声明投影），transport 只动冻结请求的伴随元数据（深冻结铁律）。

## 7. 外部事实基线（详见 04-external-facts.md）

- ZCode 有 **startplan / bigmodel** 双渠道，身份/路由按渠道档位切换（差异待核 K9）。
