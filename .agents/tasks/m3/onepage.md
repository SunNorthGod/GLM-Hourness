# 主 Agent：给你看的一页

这一块就是你说的主 Agent：每个项目里只有一个、专门跟你说话的 agent。它先问你要什么，再写方案给你批，自己从来不写文件。
完整设计在同目录的 `design.md`（0.4），加上接在它后面的那份设计文件（0.5，两份写法不同时以后一份为准）。这一页只讲你会碰到的部分。

## 你会看到什么

- 入口是 `/wish`。工作区里有项目图时，新开的空白会话输入框上面有一张「把这个工作区交给主 Agent」的卡片，点「写一句你想做的」，输入框里就填好 `/wish `；图上有没做完的目标时，还有「接着推进现有项目」。平时输入框下面有个小按钮，普通会话写「交给主 Agent」，主 Agent 的会话写「主 Agent」，点开能退出（`/wish off`）。
- 卡片上有一行黄字「主 Agent 用强一点的模型」。当前用的是 flash、mini 这类小档模型时，流程条会另起一行建议换，换不换你定，系统不替你换。
- 一个项目只有一个主 Agent，就是你唯一的对话窗口。在别的会话打 `/wish`，它会告诉你主 Agent 在哪个会话；想搬过来打 `/wish here`，原来那个会话变回普通会话。
- 访谈就是聊天：它一次问一两个开放的问题，带着自己的猜测，不让你在 A、B、C 里挑。你答一句，它马上记到项目图上。
- 要你定的事，它写成一个方案：一行题目，下面四行（背景、推荐、疑问、不做），每行一句话、重点几个字加粗，最后问你一句。你用自己的话回：同意、补充、否掉，或者说「讲细点」「说重点」。没有选项，没有按钮。
- 放行分两次。项目大的话会拆成几个模块（能单独设计、单独放行的一块）：
  - 项目放行：你看到一页，列整个项目的框架（大致怎么搭）、模块清单，和你定过的方向（每条原文照列）。你同意，这三样就定了，但这时还没有哪个模块开工。
  - 模块放行：每个模块先写自己的设计，再给你一页放行稿：做出来你会看到什么、它自己会做什么、什么时候来问你、替你定了哪些方向。你在对话里同意，这个模块才开工。
  - 项目小、不用拆的，只放行一次。
- 流程条在主 Agent 会话的输入框上面，写它走到哪一步、还差几项，例如「主 Agent · 访谈 · 需求卡 5/8」（要问清 8 项，已问清 5 项）；在等你时末尾写「等你确认」「等你批准」或「等你拍板」。它只显示，不能点。分了模块的项目，这一版的流程条只看项目这一级：项目放行后写「已放行」，这时各模块还在设计，哪个在等你放行，要看对话。
- 项目面板：主 Agent 交给你、你还没回的方案，出现在「需要你」里，显示四行，下面一行「在主 Agent 的对话里回话」，没有按钮。框架、模块清单和各模块走到哪了，由面板那一块另做「框架与模块」页，这一块和派活那一块都合入主干之后才有。

## 会自己发生的事

- 放行之后它自己一路往下做（拆活、派子 agent、审查、合入），直到做完或碰到必须问你的地方，不用你再敲命令。这一段归派活那一块，这一块做到放行为止。
- 每个子 agent 用哪个模型（审查，和最后看整体做没做成的那一遍，也算）由它自己选并记下理由，系统只记录，不替它选。这也等派活那一块。
- git 归它：什么时候合、先合哪个、冲突怎么解、要不要退回，都它自己定。会丢掉没提交的改动或改写历史的命令（`reset --hard`、`clean -f`、强推这类），系统先存一份能恢复的存档，再放行，并告诉它怎么恢复。存档只留在本机，不会被推出去。
- 主干往前走那一步，系统要核对这个提交过了合入前的检查，并自己记下证据，模型报的结果不算。这个核对在派活那一块里。这一块先上线时它还没有，所以那段时间主 Agent 往主干合没有人核对，只能靠 git 自己的记录和存档追查。
- 它没有写文件的工具，改不了代码和文档，要改就派子 agent 去。它在命令行里用重定向这类办法写文件，系统也拦。
- 项目或它手上的那个模块放行之前，它派出去的子 agent 只能读、不能写。
- 记进项目图的你的话，必须是你的原话：系统核对这些话是你在方案给出之后发的，主 Agent 编不出，也挪用不了你很早以前说的话；核对不了就不记、不放行。你随口回「嗯」「行吧」这类短话时，按你定的，它先说一遍「那我记成：……」，等你点头再记。别的会话和子 agent 想不经你同意把项目推向放行，也会被拦下，主 Agent 会告诉你一句。
- 它随时回你话，不受高峰模式影响。高峰模式的三档只管它派出去的子 agent 和重的活，不管它自己。

## 什么时候问你

- 访谈：你想要什么，做成以后日子有什么不一样，你会怎么检查它真做成了，有什么明确不要，有什么不能改、不能花、不能冒的险，没做成最可能是因为什么。每次一两个开放的问题。它能自己查到的不问，可以回头改的小事它自己定，用一句话告诉你。
- 确认需求：8 项问清后，它把需求整理成一个方案给你，你同意了才开始做设计。
- 放行项目，和之后给每个模块各放行一次，见上。
- 开发中碰到的问题分三档，判断和成批归派活那一块：
  - 可以回头改、只影响一个模块的：主 Agent 自己定，下一批问题里告诉你。
  - 要改某个模块的设计方向的：主 Agent 把这个模块退回设计，你再看一页新的放行稿、再同意一次。这一步不需要你的原话。
  - 要改整个项目框架的：要你说话，主 Agent 带着你的原话把项目退回设计，受影响的活先停。
- 同一次最多问你三件。一条回复里放第四件，系统不收，要它先问这三件、等你回完。
- 装好之后要在桌面版上验一次人设，需要改你的桌面版配置，到时先问你；建议你自己在插件管理器里设，测完自己清掉。
- 除此之外不问。

## 替你定了的方向

- 方案、你的原话和放行记录进项目图（项目仓库里的 `docs/graph/`），存档的记录进项目目录的 `.llm/`，不进 git。用户目录里只有人设这类全局项，外加一条小记录（哪个会话是这个项目的主 Agent）：它按你的规矩也该搬进 `.llm/`，这次先不搬，留给之后统一对齐。没选放在用户目录：换电脑带不走。
- 你的话由系统核对原话，核对不了就不记。没选信主 Agent 自己的转述：放行会放开子 agent 的写权限，一段编出来的话就够放开它。
- 四行由系统拼好，主 Agent 原样转给你。没选让它自己排版：你一晚上纠正过三次排版，模型照规矩写也会走样。
- 项目放行时，项目就算「已放行」，各模块各自还在设计。没选等最后一个模块放行才算：那样项目整段时间停在设计，面板分不出「框架在改」和「模块还在设计」。
- 主 Agent 可以自己把一个模块退回设计，不要你的原话；把整个项目退回，要你的原话。没选两种都要：退回一个模块只影响这一块，你会在新的放行稿上再看一遍。
- 放行稿系统只查会让你看漏的事：项目放行的稿里有每个模块和每个框架决策的标题、每条方向的原文，模块放行的稿里有这个模块的标题，你在对话里看过整页。不查小标题和行文。没选检查格式：那只会逼出凑数的段落。
- 存档只在丢工作的命令之前存，别的 git 命令不拦；存不了，或存档会被推出本机时才拒绝。没选一律拦下这类命令：git 是它的活，丢了能恢复就行。
- 存档不存被 `.gitignore` 忽略的文件（`.env`、`node_modules/` 这类）。删工作树时它们不会恢复，只记下路径和大小；要删这些文件的 `git clean -x`，要你自己在终端跑。存档也不自动清理，留到你删。没选全存：`.env` 这类秘密会进存档，存档万一被推出去就泄露了。
- 这一块先单独上线，合入前的检查随派活那一块晚一步来。没选等派活那一块一起上线：主 Agent 是自举前剩下最大的一块，等不起。

## 交给别的块的

- 派活那一块：放行之后的自动推进，选模型与记理由，开发中的三档问题与成批，主干前进时的合入前检查。认放行的方式：没拆模块的项目看项目放行那一次写入，拆了模块的看每个模块自己的放行，不看项目放行。放行前只读这条规矩只看主 Agent 当前聚焦在哪个模块，聚焦在别处时拦不住，靠派活那一块只派已批准的活来补。
- 每个模块的设计要由独立评审对照方向清单检查，违背了就挡路。编排方已定由派活那一块发起（可推翻），评审结果怎么记由它定好后交给这一块，这一块再给模块放行加一项检查。在那之前，只有主 Agent 自己对照，并在放行稿「替你定了的方向」一段写出来给你看。
- 面板那一块：读这一块定下的图上形状（模块、框架、方向清单），做「需要你」里的方案、首页每个目标下的模块进度行和「框架与模块」页。
- 规则板：这一块的 8 条拦截（不写文件、不出问答卡、丢工作的 git 命令先存档、放行前只读、转述要是原话、不列选项、目标只经确认和放行向前、会话里不用命令行改图）列在规则页的「写在代码里的规则」里，只能看。
- 规则板和循环板：它们想加带脚本的规则或条目，都走这一块的四行方案给你看，脚本原文你看过才算数，你同意后交回它们生效。
- 循环板、晨报、周报、巡检：到点要找主 Agent 所在的会话，这一块给出「主 Agent 在哪个会话」的读法。
- 指标记录：你的每次回话，系统记成同意、补充、否掉三种固定说法之一，指标记录从图上数；被拦下的次数也交给它。
- 评审留下两件小事，不挡开工，留到实现时顺手处理：本仓库自己的图上，`orch` 和 `bottom` 这两个包一级的特性带着旧的进度标记，会被新规矩读成没放行的模块，已在图上记成待办，放行前只读那一步实现时一并定；给主 Agent 看的示范题，五行要写成各自一段。

## 放行

① 放行主 Agent 的设计

背景：这份设计按你说的**两层循环**补完了，评审第 5 轮通过，只剩两处不挡路的小问题。

推荐：评审已过，**直接开工**，先做主 Agent 的开关和拦写入，再做方案和放行，最后做流程条和入口。

疑问：最没把握的是**哪些短话要复述**，你回「行」它可能多问一次，用着嫌烦就让「行」直接记。

不做：不等派活那一块**一起上线**，自举等不起，合入前的检查晚一步补。
