# 状态板块：给你看的一页（设计 0.3，评审已通过）

## 你早上打开面板，又问主 Agent

周四早上你打开右侧栏的「项目图」，首页「现在」写着：谁在跑、此刻不是高峰。你顺手在对话里问主 Agent「额度还剩多少」，它答「5 小时额度已用 42%，约 13:40 重置」。面板那条高峰和主 Agent 说的高峰读同一份数据；额度也一样，主 Agent 读的那份和 /hourness 报告里的额度一节是同一份，不各算一遍。以前晨报和周报对同一件事各取一处、偶尔对不上，这回收口到一处。

面板上另有一块「指标板」，写各模型、各版本的质量对照这类给你看的比较；这些只给你看，主 Agent 读不到，也不进它的对话。

## 对你有什么变化

1. 晨报、周报、面板、主 Agent 的回答，是同一份状态的不同显示。每件状态由管它的那个模块算一次，四处都读它，数字不会对不上。
2. 每件状态都标「给谁看」：操作要用的（高峰、额度、用量、推进停住、进度）和三个减负数字（每周被问几次、每次读多少字、等多久）主 Agent 能读、周报里会转述；只给你看的是各模型、各版本的质量对照这类比较，主 Agent 读不到。这守着原来那条规矩：这类比较不给模型看。
3. 主 Agent 不加新工具，还是用它读晨报周报那个入口，只是这个入口只会拿到能给它看的那几条。
4. 哪个模块的状态临时读不到，面板和报告在那一格写明「暂时读不到」并说原因，不拿别处的数顶上，也不猜。
5. 面板不另起一套登记，沿用现有那一套，只在上面多挂一串状态条目，不重复造。

## 要你定的

① 这件事怎样算做完

状态板块一共 6 条「怎样算做完」，写在 design.md 第 1.4 节：四处数字一致、主 Agent 拿不到只给你看的条目、报告里不含那些只给你看的比较、读不到时写明不顶替、陈旧的标出时间、用量清单不各算一遍。这些还没写进项目图，你没签过；按分工，「怎样算做完」只能你定。

我建议你放行这一页时把这 6 条一起定下，想改哪条就说「第几条改成……」，可以吗？代价：定下之后再改要你出手。
