### 第 4 组的次数与最近 5 条从哪一本流水来

`src/rules/index.ts` 的 `composeViews`：

```ts
const journal = auditPaths(dataHomes(ctx, config.home)).violations
...
records: journal === undefined ? [] : journalRecords(readText(journal) ?? ''),
```

`dataHomes` 只看规则行的 `home`，没有就取数据目录服务的 `projectHome`，与会话所在的项目无关。代码规则所在的几行都不写这里：guard 行 `projectJournal(name, cwd => projectHomeFor(ctx, config.home, cwd))`，graph、loops、design 同样；metrics 行是 `projectHomeFor(ctx, undefined, cwd)`。`projectHomeFor` 的次序是行的 `home`、会话项目的 `<根>/.llm`、数据目录服务。出厂补丁里 `glm-hourness/data` 与 `glm-hourness/rules` 的 `config` 都是 `{}`，用户 profile 按补丁注释只给 memory、workflow、hourness 配 `home`。于是在生产上：

```
guard/graph/loops/design/metrics 的拒绝 ──> <项目根>/.llm/audit/violations.jsonl
规则行的门（rules:*）               ──> <数据目录 projectHome>/audit/violations.jsonl（或没有）
view.json 的 code[].denials7d/last  <── 后者
同页的 rules/denials 条目（guard 视图）<── 前者
```

结果是第 4 组每条代码规则写「最近 7 天拦下 0 次」、「讲细点」是「最近没有拦下的记录」，页头的 `rules/denials` 条目却列出拦下：同一件事两处算，正是状态板块 §3.1 要收口的那种。数据目录服务的 `projectHome` 是固定目录时，第 3 组与 `rules:files-only` 的次数还会把别的项目的记录算进来，因为读出的记录没有按项目筛。（confirmed：上面几处代码都读到了；生产上的表现取决于 profile，likely。）

测试与探针看不出来：探针的 `dataRows` 给 guard、graph、loops、design 和数据行配了同一个 `<dir>/home`，几本流水碰巧是一本；`tests/rules-row.spec.ts` 的拒绝也写在规则行读的那本里。metrics 行在探针里写项目根的 `.llm`，所以 `metrics:metrics-files-only` 的拒绝今天在探针里也上不了页，只是没有检查覆盖它。

这条路径是计划第 7 节第 1 批与 FEAT-001 写定的（「`rowJournal` 用的同一个 `dataHomes(ctx, config.home)`」），实现照做了，毛病出在计划。ORCHESTRATION §16.11 写规则板的拦截「写进 guard 写的那一份」，而规则行门的 `rowJournal` 并不按项目取目录，这是 main 上就有的出入，不在本次范围；本次要做的是页面读对那一本：读 `projectHomeFor(ctx, config.home, cwd)` 的项目流水（guard 状态视图读的同一本），规则行门那本不是同一个文件时也读进来，按行去重。

### 周期计算的开销

`every(guarded(() => pageView.write()), BEAT_MS)` 每 15 秒对每个有已知会话的项目调一次 `composeViews`：`readText`（`readFileSync`）读整本违规流水、逐行 `JSON.parse`、跑 `ruleStats`，再调 `collectStatus`，其中 guard 状态视图同步把项目流水整本再读一遍。内容去重只省掉写，不省读。违规流水只增不减，这份开销随时间线性涨，而且不管面板开没开都在宿主事件循环上跑。（likely，影响取决于流水大小。）

### 测试覆盖

计划列出的各组数据、撤下三种写法、`journalRuleOf` 不串、`homeLine`/`guideLine` 各三种与 60 码点、板的对象不变、源的失败与轮询、只读静态检查都有用例（`rules-view` 13 例、`rules-row` 增 7 例、`rules-panel-model` 16 例）。没有覆盖：规则行与 guard 一类的行写在不同流水目录时第 4 组的次数；`metrics:metrics-files-only` 的拒绝上页。
