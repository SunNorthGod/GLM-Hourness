# 指标记录：给你看的一页（设计 0.6）

## 一个周一傍晚（示意）

你做什么：主 Agent 这几天在照片整理工具项目里做模块。周一 18:30，你敲 /hourness，再到插件仓库的命令行敲 npm run metrics -- summary --project <照片整理工具的目录>。

你看到什么：

```
/hourness 里
今天：派出 5 件，做完 3 件，等你 2 件，检查没过 1 次
额度：停了 1 次，共 43 分钟，自己接上 1 次
记录：最早 11 月 3 日，今天 212 条，这次启动以来丢了 0 条；上次自查没有问题

npm run metrics -- summary 多出的
问你 8 次：确认推荐 6 次，选方向 2 次；你说「你定」1 次
主 Agent 的问话被系统退回重写 2 次（太长）
你原样同意 8 次里的 5 次；每步积分按模型分列
```

数字是举例。/hourness 经主 Agent 的对话给你，只有事实；同意的比例、按模型比较这类像分数的数只在命令行里。指标记录要等这个插件仓库改用插件自己开发以后才动手做。

## 对你有什么变化

- 数都由系统记：每次调模型的 token、积分和用时，每次工具调用的结果，每次问你、你等了多久、怎么回的，都由系统写，模型自己报的数不算。只记数和编号，不记对话、文件内容和命令全文。
- 新问法试行的效果有数：每种问法问了几次、你说「你定」几次、主 Agent 的问话因太长、用词不合或一次超过三件被系统退回几次，都记下了。
- 记录放在项目里：在项目的 .llm 目录，不进 git，你的用户目录里没有。代价是 git clean -fdx 或换电脑重新克隆以后，记录从头开始，只有项目图的历史能补回来。
- 只有你能删：整天的记录只有你在命令行里删得掉；防误写的规则装上以后，agent 去写、去删这些文件会当场被拦，按规则编号记下。要放开，对主 Agent 说一句。
- 出了问题会说：写不进去不挡你的活，先排队重试；缺了行、文件被删，启动后和每天一次的自查会查出来，写在 /hourness 的末行。

## 替你定的

替你定了 39 件事，列在设计第 15 节，都能推翻。其中一件和你定的规则一启用就拦有出入（你的原话是「试运行规则啥的直接拦就行了，这样反而有问题好发现」）。我定了：指标记录先启用，防误写的规则晚一步装，因为这条规则要等管拦截的那一块先合入；中间这段的误写和误删只能事后查出来，不对就说。

## 要你定的

每件回「可以」就按我的建议定，两件可以分开答。

① 指标记录要分十步做，设计第 1.4 节写了 24 条检查，要看就跟主 Agent 说。每一步怎样算做完，只有你能定。我建议十步都照这 24 条检查判断做没做完，因为这些检查都由系统自己跑，不用你逐条读，可以吗？

② 宪章写着指标不给模型看，派活那一块的设计却让主 Agent 在周报里转述比率，两处说法不一样，要你定用哪个。宪章另要求每周报四个减负数字：每周问你几次、每次读多少字、你等了多久、因你的决定返工几次。我建议周报里主 Agent 只转述这四个数，其余比率只放命令行，因为比率最像分数，进了对话模型容易追着它跑，可以吗？代价是看比率只能自己敲命令，现在做的面板也不显示。
