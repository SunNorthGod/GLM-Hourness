# 循环板：给你看的一页

这一块就是你说的循环任务面板：到点了或碰到某件事，就去做一件事。做完之后，晨报、巡检、交回之后派审查这些事都在一块板上看得到，不再藏在代码里；你也能让主 Agent 加你自己的，比如服务器巡查。完整设计在同目录的 `design.md`（0.2），这一页只讲你会碰到的部分。

## 你会看到什么

- 项目面板首页的页脚多一个「循环板 ›」。页面分三组：碰到某件事就做的、到点做的、本项目加的。
- 每一项写着什么时候、做什么、上次和下次，下面一行灰字写是谁带来的：「项目编排带来的 · 只能看」「GLM 通道带来的 · 只能看」，或者「你在对话里加的」，后面跟着你当时的原话。
- 出厂一共 20 项。编排层 16 项：设计放行之后开始推进、交回之后派审查、审查过了之后合入、停下之后问你、活都关了之后派整体审查、合进主干之后跑一遍完整检查、重启之后接上、改完文件就跑检查、同一件活第三次返工之前停下问你、依赖文件变了之后查依赖、有事等你超过 24 小时再说一次、高峰开始时按档位收放、高峰结束时接上挪开的活，以及晨报（每天 08:30）、周报（周一 09:00）、夜间巡检（每天 02:30）。GLM 4 项：高峰开始时提醒模型、看状态时读额度、额度快用完时告诉你、登录失效时提醒你重新登录。
- 页面上没有按钮。要加、改、删你自己的，跟主 Agent 说一句；要删也可以在输入框打 `/loops delete 名字`，删错了 7 天内打 `/loops restore` 能恢复。
- 插件带来的只能看，不能改、不能关。高峰档位照旧在规则板，用 `/rules peak` 改。

## 会自己发生的事

- 到点告诉主 Agent 的几项交给 DSH 自带的定时服务，DSH 的自动化任务页里也看得到；在那里改了不算数，循环板会改回来，并在页面上写一行。
- 你加的命令（比如服务器巡查）在你的电脑上、项目目录里按时跑，拿不到 DSH 的凭证；过了不打扰主 Agent，没过才告诉它。
- 同一件事短时间里来好几次，合成一次；一小时里次数太多的，合进下一次，不丢。
- 高峰选了不做：规则板让哪个会话停着，循环板就替它攒着消息，高峰过了一起交。
- 默认是少做：高峰结束时，主 Agent 如果闲着、高峰里干过活、又不是在等你回话，就叫醒它一次，把挪到高峰之后的活接上。
- GLM 额度快用完、登录失效这种整个账号的事，只告诉最近一次干过活的那个主 Agent，每件说一次。
- 每次跑了什么、结果怎样，都由系统自己记下，不靠模型报。

## 什么时候问你

不问。只有你自己要加一项的时候，主 Agent 会把它写成四行给你看，你说可以，它才记下。

## 替你定了的方向

- 到点跑命令用循环板自己的钟，不经 DSH。没选全交给 DSH，因为那样每次命令跑完都要叫醒主 Agent、在你的对话里多一回合。代价是命令类的不能写 cron。
- 插件的行为由各自的插件当数据交上来，循环板只管显示和执行。必须在别处当场做的（检查器、高峰的收放、GLM 的提醒），这里只列出，不另做一遍。
- 加一项只在对话里说，不做成命令：一项要写清时间、做什么和命令原文，在输入框里打不清楚。
- 高峰结束时叫醒主 Agent，只在它闲着、高峰里干过活的时候叫，每个工作日至多一次。
- 「自己触发自己」只算循环板自己做的事引起的。主 Agent 修好问题再合进主干，照常再检查一遍，不会被当成打转拦下。

## 交给别的模块的

- 编排层的执行那一块：交上来的十项照新的格式写；新加两件：主干在系统之外前进时也报一声，好让完整检查也跑；高峰里因为没活干被挡住的自动推进，高峰过后由系统恢复。
- 规则板：加一个「这个会话此刻是不是因为高峰停着」的问法，补上高峰刚开始时可能多花的那一步。
- 主 Agent 把事情交给你看的那一块：四行的提议能挂上循环板的提议，你同意之后循环板才记。

## 放行

① 放行循环板的设计

背景：这份设计按你说的**都放到明面上**改好了，插件的默认项由插件自己交上来，页面只看不点。

推荐：评审通过后**直接开工**，先做格式、存档和执行，再做页面。

疑问：最没把握的是**高峰结束叫醒**主 Agent，你嫌打扰就说一声，改成不叫。

不做：不把**跑命令**也交给 DSH 定时，那样每次都会在你的对话里多一回合。

这样放行可以吗？
