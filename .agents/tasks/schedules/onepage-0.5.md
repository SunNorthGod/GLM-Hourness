# 循环板：给你看的一页

这一块就是你说的循环任务面板：到点了或碰到某件事，就去做一件事。做完之后，晨报、巡检、交回之后派审查这些事都在一块板上看得到，不再藏在代码里；你也能让主 Agent 加你自己的，比如服务器巡查。完整设计在同目录的 `design.md`（0.4），这一页只讲你会碰到的部分。

## 你会看到什么

- 项目面板首页的页脚多一个「循环板 ›」。页面分三组：碰到某件事就做的、到点做的、本项目加的。
- 每一项写着什么时候、做什么、上次和下次，下面一行灰字写是谁带来的：「项目编排带来的 · 只能看」「GLM 通道带来的 · 只能看」，或者「你在对话里加的」，后面跟着你当时的原话。
- 出厂一共 20 项。编排层 16 项：设计放行之后开始推进、交回之后派审查、审查过了之后合入、停下之后问你、活都关了之后派整体审查、合进主干之后跑一遍完整检查、重启之后接上、改完文件就跑检查、同一件活第三次返工之前停下问你、依赖文件变了之后查依赖、有事等你超过 24 小时再说一次、高峰开始时按档位收放、高峰结束时接上挪开的活，以及晨报（每天 08:30）、周报（周一 09:00）、夜间巡检（每天 02:30）。GLM 4 项：高峰开始时提醒模型、看状态时读额度、额度快用完时告诉你、登录失效时提醒你重新登录。
- 页面上没有能改东西的按钮。要加、改、删你自己的，跟主 Agent 说一句；要删也可以在输入框打 `/loops delete 名字`，删错了 7 天内照删除时给你的那条 /loops restore 打一下就能恢复。
- 插件带来的只能看，不能改、不能关。高峰档位照旧在规则板，用 `/rules peak` 改；少做那一档的「高峰里同时至多 1 个 GLM 子 agent」也写在高峰那两项下面。
- 高峰开始和结束时的那两项写着「项目编排带来的」：高峰几点开始几点结束是 GLM 通道给的，到点按档位收放、高峰后接上停住的活并叫醒主 Agent 是项目编排做的。
- 主 Agent 的会话被你归档了，或者找不到了，页面最上面和首页会写「主 Agent 的会话已归档：在一个会话里打 /wish here」。在那之前，给主 Agent 的消息先存着（存 24 小时），不会投进一个谁也看不到的会话里。

## 会自己发生的事

- 到点告诉主 Agent 的几项交给 DSH 自带的定时服务，DSH 的自动化任务页里也看得到；在那里改了不算数，循环板会改回来，并在页面上写一行。
- 循环板只删它自己建的、确实没用了的提醒，删之前把那条提醒原样记下 30 天，「最近跑过的」里也写一行。它看不清主 Agent 的会话时（会话开在另一个窗口，或者读不到它的状态），晨报、周报、巡检这几条原样留着，一条不删，页面上写「看不清」。
- 你加的命令（比如服务器巡查）在你的电脑上、项目目录里按时跑，拿不到 DSH 的凭证；过了不打扰主 Agent，没过才告诉它。
- 同一件事短时间里来好几次，合成一次；一小时里次数太多的，合进下一次，不丢。
- 同一件事被报了两遍（比如重启后又补报一次），只做一次，第二遍在「最近跑过的」里写着；真的又发生了一次（比如又重启了一次），照常再做。
- 你在两个 DSH 窗口里开着时，循环板跟着主 Agent 的会话，在它所在的那个窗口里跑。那个窗口一直不接手时，过 5 分钟页面会写「这块板交不过去」。
- 高峰选了不做：规则板让哪个会话停着，循环板就替它攒着消息，高峰过了一起交。
- 高峰里主 Agent 手上只剩挪到高峰之后的活时，自动推进先停着，不来问你；高峰一结束，系统把它接上并叫醒主 Agent，少做和不做都这样。没有停住的自动推进时，默认的少做档下，主 Agent 如果闲着、高峰里干过活、又不是在等你回话，也叫醒它一次。主 Agent 真没事可做、已经在问你的，高峰结束时不替你接上，还是等你说。
- GLM 额度快用完、登录失效这种整个账号的事，只告诉最近一次干过活的那个主 Agent，每件说一次。
- 每次跑了什么、结果怎样，都由系统自己记下，不靠模型报。

## 什么时候问你

循环板自己不问你；板上「停下之后」「等你太久」与晨报这几项，本来就会让主 Agent 在对话里把事交给你。只有你自己要加一项的时候，主 Agent 会把它写成四行给你看，你说可以，它才记下。会跑命令的那种，四行下面多一段命令原文和注意事项，是系统自己附上的，不是主 Agent 转述的；主 Agent 没把这一段给你看，你说可以也不算数。

## 替你定了的方向

- 到点跑命令用循环板自己的钟，不经 DSH。没选全交给 DSH，因为那样每次命令跑完都要叫醒主 Agent、在你的对话里多一回合。代价是跑命令的那几项只能按每隔多久、每天几点、每周几点来定，写不了更复杂的时间规则。
- 你同意一条会按时跑的命令之前，看到的是命令原文。命令原文太长（超过 400 个字）的不收，要先写成项目里的一个脚本。代价是这种提议在对话里多一段字。
- 主 Agent 的会话归档了，循环板不自己挑一个会话接着投，等你用 /wish here 指定。代价是在那之前，晨报、交回之后派审查这些都停着。
- 循环板看不清主 Agent 的会话时宁可留着提醒、不删。代价是读不到归档状态的时候，提醒可能照样投进一个已归档的会话，页面会写「看不清」。
- 插件的行为由各自的插件当数据交上来，循环板只管显示和执行。必须在别处当场做的（检查器、高峰的收放、GLM 的提醒），这里只列出，不另做一遍。
- 加一项只在对话里说，不做成命令：一项要写清时间、做什么和命令原文，在输入框里打不清楚。
- 高峰结束时叫醒主 Agent：自动推进因高峰停住时，接上它再叫醒，每段高峰至多一次；没停住时，只在少做档、它闲着、高峰里干过活的时候叫，每个工作日至多一次。
- 「自己触发自己」只算循环板自己做的事引起的。主 Agent 修好问题再合进主干，照常再检查一遍，不会被当成打转拦下。

## 交给别的模块的

- 编排层的执行那一块：交上来的十项照新的格式写，每项补一句为什么有它；每次报事情时写清是哪一次，免得真的又发生了一次的事被当成重复、没人去做；有人不经系统直接改了主干时也报一声，好让完整检查也跑；高峰里只剩挪开的活时，自动推进先停着、不算没进展，高峰结束时由循环板请它接上。原来说的「因为没活干被挡住的自动推进，高峰过后由系统恢复」不做了：那种是真没事可做，该问你。
- 规则板：它已经按新的分工改好了，这里不再要它改东西。
- 主 Agent 把事情交给你看的那一块：四行的提议能挂上循环板的提议，你同意之后循环板才记；会跑命令的提议，它在四行下面附上命令原文，并在记下你的同意之前核对主 Agent 确实给你看过。

## 放行

① 放行循环板的设计

背景：这份设计按你说的**都放到明面上**改好了，插件的默认项由插件自己交上来，页面只看不点。

推荐：评审通过后**直接开工**，先做格式、存档和执行，再做页面。

疑问：最没把握的是**高峰结束叫醒**主 Agent，你嫌打扰就说一声，改成不叫。

不做：不把**跑命令**也交给 DSH 定时，那样每次都会在你的对话里多一回合。
