# 一页稿：把知识文档放到 AI 手边（docs-at-hand）

版本 0.3（2026-11-07）。完整设计在同目录 `design.md`（0.3；0.2 评审通过，0.3 的改动处另审一轮，记录见 `review.md` 与设计 §14）。0.3 按人 02:24 的话「尽量融合进我们的流程内而不是加越来越多的东西」收敛：不新增插件行、不新增文件格式、不新增规则、不新增事件。

## 先说查到的事

DeepSeek Harness 自己会读子目录里的 `AGENTS.md`，但有三个条件：用的是它原生的读、写、改文件工具；文件在会话的工作目录之下；读写成功之后的下一次请求才带上。用命令行、搜索工具碰到的目录不算。GLM 那条路上一份都读不到，因为我们给 GLM 换成了 ZCode 的工具名，它认不出来（另有一条线在查怎么修）。这些是读了源码、又在沙盒里用假模型跑了三遍确认的，没花积分。

## 四件事（0.3）

1. **组件旁放文档：一个文件。** 每个组件目录放一个 `AGENTS.md`：这块是什么、不能动什么和为什么、依据哪几个决定的编号，再加「流程」（流程图）与「案例」（几句话一条的端到端案例）两节。待办、进度、决定的结论不写进去，只写编号，状态都在项目图上。DSH 加载子目录 `AGENTS.md` 时这些一并带上，约定只有一个文件。
2. **打开文件就送到手边：并进经验板，不加新插件。** 经验行（已启用）在 AI 读或改一个文件之后，把按这个文件匹配到的经验、该组件文档里列的决定在图上此刻的样子、跟这块有关的没做完的活，合成一条提醒；组件文档正文只在 DSH 没有自己送到时补上（GLM 那条路补，修好之后就不用补）。一次调用一条提醒。因为经验行是出厂启用的，这一件合入后桌面版上读到有经验的文件就会多一条提醒；合入按桌面版的流程走（先 CDP 关桌面版再合入、重建、启动）。
3. **改代码不改文档时核对（等 M7 合进主干，本轮不做）：** 不加规则。交活的结构里多一行「文档是否仍对」，交活处理发现改了有文档的组件而这一行没写，就在摘要批注里写一句；审查清单多一条核对它。只提示，不拒绝交活。
4. **每天傍晚查漏：一项默认条目。** 循环板加一项每天 18:05 的默认条目，叫主 Agent 自己只读地查所有工作目录和分支有没有没提交、没推送的东西，有就跟你说一声，干净就一句话不说；不会提交也不会推送。不新增事件和扫描代码。代价：每天多一个很短的回合（在 GLM 高峰之后）；数是主 Agent 自己报的，不是系统扫的。和别的默认条目一样，只能看不能改，要停得关掉整个循环板；想换时间可以自己加一条。
