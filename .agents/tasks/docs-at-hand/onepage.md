# 一页稿：把知识文档放到 AI 手边（docs-at-hand）

版本 0.2（2026-11-07）。完整设计在同目录 `design.md`（0.2，独立评审通过，评审记录 `review.md`）。

## 先说查到的事

DeepSeek Harness 自己会读子目录里的 `AGENTS.md`，但有三个条件：用的是它原生的读、写、改文件工具；文件在会话的工作目录之下；读写成功之后的下一次请求才带上。用命令行、搜索工具碰到的目录不算。GLM 那条路上一份都读不到，因为我们给 GLM 换成了 ZCode 的工具名，它认不出来。这些是读了源码、又在沙盒里用假模型跑了三遍确认的，没花积分。

## 四件事

1. **组件旁放文档**：每个组件目录放三份：`AGENTS.md`（这块是什么、不能动什么和为什么、依据哪几个决定）、`FLOW.md`（流程图）、`CASES.md`（几句话一条的端到端案例）。待办、进度、决定的结论不写进去，只写决定的编号，状态都在项目图上，所以不会两处对不上。给所有动手的 AI 看。代价：每个组件要有人写一次初稿（一件文档活），之后改代码的人顺手维护。
2. **打开文件就送到手边**：AI 读或改一个文件时，系统把这个组件的文档、项目图上跟这块有关的决定和没做完的活、经验板里跟这个文件有关的坑，合成一条提醒放在它眼前；DeepSeek 自己会送的那份不重复送。给所有会话，GLM 与非 GLM 都一样。代价：一个新的插件行（默认关，验过再开），每个组件在一个会话里多一段提醒文字。
3. **改代码不改文档时核对**：交活时，改了某个组件的代码而它的文档这一批没动，有两种管法（下面第 2 问）。给主 Agent 和审查的 AI。代价见第 2 问。要等 M7 合进主干。
4. **每天傍晚查漏**：每天 18:05 查一遍这个项目所有工作目录和分支，有没提交的改动、提交了没推送的，就叫主 Agent 跟你说一声；它只汇报，不会因为这条提醒自己去提交或推送；都干净就不出声。给你。代价：每天一次只读的 git 检查，有东西时主 Agent 多跑一回合（在 GLM 高峰之后）。这一项和别的默认条目一样，只能看不能改，要停得关掉整个循环板。

## 建议

四件都做，先后：第 4 件 → 第 2 件连同第 1 件的文档格式 → 第 1 件的生成方式连同第 3 件。第 4、2 件不等别的线，做完马上有用（经验板里 21 条经验有 16 条带文件路径，按文件送今天就送得出东西）；第 1 件的生成和第 3 件要改 M7 的派活说明与交活结构，等 M7 合进主干后和「返工要写原因」那件一起做。合计约 5–6 天。

## 等你定的三件

**1. 范围与先后。** 选项：A 四件都做，按上面的先后；B 做第 2、4 件，连同第 1 件的文档格式（不碰 M7：派活说明里那一句、交活核对都不做）；C 只做第 4 件。推荐 A。理由：第 1、3 件才让文档长出来、不过期，只做 2、4 的话手边送的主要是经验和决定编号。另外，要不要给本仓库自己的组件补写文档不在这四件里，你说要再派（每个组件一件小活）。

**2. 改了代码没改文档时怎么管。** 选项：甲，审查时记一条意见，不挡；乙，交活时必须说一句「文档为什么还对」或者改了文档，没说就退回让它补一句，审查再看这句话对不对；（丙，必须改文档才收，不推荐：改个错字也得硬改文档）。推荐乙。理由：视频说这是最不能漏的一步；乙只要一句话，只在有组件文档的地方出现；甲碰上「不审」的活就看不到了。乙会在规则板上多一条规则，误拦了你一句话就能撤。

**3. 每天查漏放在哪。** 选项：甲，循环板自带的 18:05 那一条（本稿的做法）；乙，并进 M7 的凌晨 2:30 夜间巡检；丙，每天 18:05 叫主 Agent 自己跑 git 查。推荐甲。理由：甲不等 M7、干净时不打扰、数是系统自己查的；乙在半夜，你不在；丙每天都要叫醒主 Agent，数是它自己报的。

## 替你定了、你可以推翻的

- 目录里有 `AGENTS.md` 就算一个组件，不另外登记；三份文件的名字如上。
- 提醒有长度上限，同一个会话里同一块只送一次，压缩后再碰到才再送。
- 第 4 件的时间是 18:05，避开 GLM 高峰；你想换时间，可以在循环板上另加一条（默认那条仍在）。

## 顺带发现（不在这件里）

GLM 那条路上，任何项目子目录里的 `AGENTS.md` 都进不来（包括你自己写的）。第 2 件在两个包都装时补上了组件文档这一部分；根子在 GLM 通道包换工具名的做法，建议另开一件定怎么修。
