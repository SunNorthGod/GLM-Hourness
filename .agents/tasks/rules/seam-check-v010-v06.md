# 接缝核对：规则板设计 0.10 与循环板设计 0.6（2026-10-30）

对照的文件：`.agents/tasks/rules/design.md`（0.10）、`.agents/tasks/schedules/design.md`（0.6）、`docs/CHARTER.md`（0.7，提交 `f2faa6f`，不动）、两份记图草稿 `rules/graph-ops-v010.json` 与 `schedules/graph-ops-v06.json`。依据的裁定：`design-context.md` 的「Both boards are hook-style; storage scope」「Main agent and peak; stale entries; hook seam」「Worked examples for the agent」「Check entries seam」，以及 `rules`、`schedules`、`m4` 节点上的批注（`node .agents/tasks/m1-l4/show-nodes.mjs …`，节点比文档新的以节点为准）。前一轮的报告是同目录 `seam-check-v09-v05.md`，本报告沿用它的格式与归属裁定。

## 没有定下的

1. 采用机制的差异（第 5 点）：规则板按拍板里的 `attachDigest` 记号核、循环板按脚本字节与条目块一致核。两者对「人同意过的那份」判得一样严、都排除有意伪造，归各板自己的存储，没有强行统一（同 v09-v05「没有定下的」第 2 条对 `repin` 做法的处理）。循环板已导出 `attachDigest`，评审若要两板用同一种核对（都核 `attachDigest`），再定；这是加强、不挡路。
