# 规则板：给你看的一页

这一块就是你说的「规则」板块：一件事要发生时，让不让做。
项目里会挡住动作的规矩，都在这块板上看得到。
出厂只带一条默认规则：GLM 峰谷定价，外加一个你能选的高峰模式。
完整设计在同目录的 `design.md`（0.10），这一页只讲你会碰到的部分。

## 你会看到什么

- 项目面板首页的页脚多一个「规则板 ›」。
- 页面从上到下七组：
  - 会挡住动作的门：合入前的检查清单、必须全审的改动。每一条照项目图上你批过的原文列出，写明谁在执行、现在生效没有。系统还认不出的那几条，旁边写「暂不强制」。
  - 默认规则与高峰模式：现在是不是 GLM 高峰（工作日 14:00–18:00）、到几点；高峰模式是哪一档、谁选的。
  - 你定的规则：出厂没有。
  - 写在代码里的规则：比如不许写工作区外的文件、项目图只经图工具改、代码里带的那几条检查。只能看，规则板只把它们列出来。
  - 信号与检测器：你定义的开关（比如「代码冻结」）、你加的检测器测出来的值。出厂都没有。
  - 在等的工作：被规则推迟的事，在等什么、从几点开始。
  - 提议与恢复：主 Agent 提给你的规则在哪里等你回话；存档坏过、按变更记录重建过的，或仓库里的规则文件被规则板以外改过的，写明时间和原因；换电脑后没有你看过原文记录的带脚本规则，写「没有你看过原文的记录」。
- 插件带来的条目写「项目编排带来的 · 只能看」。
- 页面上没有按钮。能改的地方下面各有一行：「要改：跟主 Agent 说……，或在输入框打 /rules ……」。
- 首页「现在」里，高峰时有一行「GLM 高峰中，到 18:00 · 高峰模式：少做」。有事在等规则放行时，写有几件。

## 高峰模式

- 三档：无影响、少做、不做。默认是少做。
- 无影响：照常做，只提醒。
- 少做：同时至多 1 个 GLM 子 agent；练习题、对照实验、大的评审挪到 18 点以后；必要的活照做。
- 不做：GLM 的活停下排队，18 点以后接着做。
- 换档：跟主 Agent 说「高峰改成不做」，或在输入框打 `/rules peak 不做`。不想受影响，打 `/rules peak 无影响`。
- 上手页第 4 块也讲这几句。
- 只装了编排层、没装 GLM 通道时，没有高峰时段，高峰模式不起作用，页上写明。

## 会自己发生的事

- 主 Agent 每一步都从系统的提醒里知道：现在是不是高峰、哪一档、这一档要它做什么。它不用自己算时间。
- 主 Agent 不受高峰影响：三档都不拦它的工具调用、不停它的活，它随时回话、随时在对话里跟你商量。高峰只管 GLM 子 agent 与自报的脚本。
- GLM 会话照旧在每段高峰的第一步收到一句计价提醒。各档怎么说，由 GLM 通道那一块写。
- 少做的高峰里：主 Agent 再派一个 GLM 子 agent 会被挡回去，写明到几点；自报可以挪的脚本（例如练习题），不管谁去跑，高峰里都先排队，18 点以后再跑。
- 高峰里主 Agent 把能做的做完、只剩挪到 18 点以后的活时，自动推进先停着，不来问你。
- 高峰结束时，循环板把停着的推进接上，叫主 Agent 接着做挪开的活。
- 不做的高峰里：GLM 子 agent 的操作排队，它们的自动推进暂停；18 点以后系统恢复推进，叫它接着做。主 Agent 自己照常回话。
- 你定的规则在事情发生的那一刻执行：该拦的拦下，该等的排队。条件解除后 30 秒内，系统叫原来的 agent 再试；原来的子 agent 已经结束的，交给派它的主 Agent。
- 换电脑、新克隆项目或删掉运行记录后：规则照仓库里的文件读回来；带脚本的规则只有在项目图上有你看过原文、拍过板的记录时才跑，没有的先列「没有你看过原文的记录」、不跑，等你同意。`/rules recovery 文件 照改` 之后新加或改过的脚本也一样等你同意才跑。
- 读不出是不是高峰时，三档都不拦，页上写明原因。
- 规则板自己出问题时也是放行，并在页上说出来。
- 你加的检测器先试运行：只记下它会挡哪些事，不真挡。你说转为生效才生效。
- 每一次判定、排队、叫醒，你的每一次操作，都由系统自己记下，不靠模型报。

## 什么时候问你

- 主 Agent 想加、改或撤一条规则时，在对话里给你看一个方案四行。你说可以才生效；你补充或说不行，什么都不变。
- 你也可以先开口，比如「今晚 21 点以后别推送」。主 Agent 把要写的规则给你看，你同意后生效。
- 仓库里的规则文件被规则板以外改过（git 拉取、切换、回退或手改），或存档里出现不是规则板自己写的记录时，页上列出来，等你打 `/rules recovery <编号> 照改` 或 `/rules recovery <编号> 忽略`。
- 除此之外不问。高峰里主 Agent 没别的活可做时也不问；循环板没装上时例外，页上写明。默认少做是你定的，不再问。

## 替你定了的方向

- 少做时同时至多 1 个 GLM 子 agent。没选「同时能派的活的一半」：那个数会随配置变，默认配置下也是 1。
- 这个上限数所有 GLM 子 agent，写代码的、做审查的、跑检查的都算。没选只数写代码的：你点名要挪的大的评审是审查。
- 上限由派活那一块执行，规则板只给出这个数。派活那一块还没装上时，这一条只是提醒主 Agent。
- 高峰里停住推进是派活那一块的事，高峰结束时接上推进、叫醒主 Agent 是循环板的事。规则板只告诉它们现在是不是高峰、哪一档、主 Agent 手上的活是不是被高峰挡着。
- 发给模型的高峰提醒归 GLM 通道那一块，规则板不改那句话。
- 规则只有你能定。主 Agent 和子 agent 只能提议，检测器只能测值。
- 在等的工作上可以「放行这一次」，不做档上可以「这个会话本次高峰照常做」。这两样只改一件在等的事，不算动了默认规则。你觉得算，就去掉后一样。
- 主 Agent 不受高峰影响，所以不做档里它照常回话，你在对话里换档也随时都通，不用再靠打 `/rules peak` 兜底。
- 规则板被关掉时，先恢复不做档停下的推进，再退出。
- 规则存进项目仓库，跟项目图挨着（`docs/rules/`）；运行记录存进项目目录、不进 git（`.llm/rules/`）；不再写你的用户目录。按项目分开。
- 写在代码里的规则原地不动，规则板只列出来。
- 搬进 DSH 里自己开发自己之前，规则板先只做最小一片：高峰档位与少做的上限两项，别的随整块一起做；这一片是整块设计的一部分，不会推倒重来。

## 交给别的模块的

- 派活那一块：派 GLM 子 agent 之前读一次上限；高峰里主 Agent 只剩被挡着的活时停住推进、不问你，并留一个把推进接上的动作。
- 循环板：高峰结束时先跑这个动作接上推进，再叫醒主 Agent。
- GLM 通道那一块：高峰提醒按档位换说法，并改写编排说明里讲高峰提醒的那一节；脚本自查时把高峰几点结束、等了多久一起交来。
- M4 那一块：代码里会挡住动作的那几条规矩由它定，规则板原样列出，不另写一份；它读违规记录的那几种标记，规则板写清要哪几种。
- 主 Agent 把事情交给你看的那一块：四行的方案能挂上规则板的提议，你同意之后交回规则板生效。规则板的这一部分等它做完再上。
- 面板那一块：上手页第 4 块讲高峰模式的那几句由它写，和规则页的意思一致。

## 放行

① 放行规则板的设计

背景：这份设计按你说的**默认少做**、**规则进仓库和项目目录**补完了，会挡住动作的规矩都在这块板上，页面只看不点。

推荐：评审通过后**直接开工**，先做高峰档位与少做上限这一小片（搬进 DSH 自己开发要用），再做判定、存档、提醒、排队和页面。

疑问：最没把握的是**同时至多 1 个**，你嫌慢就说一声，改成 2 个。

不做：不让规则板自己**叫醒主 Agent**，交给循环板，免得两处都叫。

这样放行可以吗？
