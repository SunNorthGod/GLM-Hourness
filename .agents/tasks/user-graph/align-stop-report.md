## 还开着的挡路发现

1. MEDIUM，`live` 的定义（design.md §2.5 第一段）。定义写成「`status` 是 `proposed` 或 `approved`，且祖先也是」，并说特性与任务也用同一个函数。引擎的状态集合还有 `doing`、`done`，特性与任务大部分时间在这两个状态，所以按字面所有进行中和做完的特性、任务都不是 `live`。结果是服务者、叶子、孤儿判定全部落空，§2.9 夹具的 22 个步骤全变成「没人负责」，与同一节「叶子的状态：`done` 是做完，`doing` 是在做」也自相矛盾。修法是一句话：`live` 改为 `status` 不是 `dropped`、`superseded` 且祖先同样不是（对只存四种状态的用户节点等于 `proposed` 或 `approved`），并在验收第 19 条加一例。
2. MEDIUM，写入规则 W1 至 W5 的检查范围（design.md §3.4）。写的是「对要写的节点用写后的整图检查」，没有说只查本次新增或改动的部分。设计自己允许存量状态：任务的 `serves` 指向后来被废弃的步骤（§4.2、§4.3）。按整节点检查，主 Agent 对这个任务做 `graph_status done` 或改正文会被 W2 拒绝，提示还指向错误的正路。修法也是一句话：W1 至 W5 只查本次写入新增或改动的连线、`kind`、证据，存量连线不挡别的写入；验收第 11 条加一组用例。

另有 6 条 LOW（`design-review-3.md` 发现 3 至 8），不挡路。
