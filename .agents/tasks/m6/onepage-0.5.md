# M6 用量与高峰：给你看的一页

这一块管 GLM 的三件事：额度还剩多少、积分怎么算、高峰时怎么办。做完之后，你不用再去 BigModel 控制台查额度；高峰时练习题会先停下，说明 18 点以后再跑。
完整设计在同目录的 `design.md`（0.5），这一页只讲你会碰到的部分。开工在自举开始之后，由 DSH 里的主 Agent 做。

## 你会看到什么

- 敲 `/glm-status` 或 `/hourness`：现在是不是高峰、到几点；5 小时额度和每周额度各用了多少、几点重置、照现在的速度什么时候用完。MCP 工具调用的额度只写已用多少和几点重置。每一行都写着是按什么算出来的。
- 这些额度数字来自服务端，ZCode 等其他软件用掉的也算在内。命令等额度至多 3 秒，来不及就先用上一次的读数，并写明正在读取。
- `/hourness` 里的用量数字只算经 DSH 发出的请求，这一点会写明；10 月 29 日删掉的 806 条旧记录单独写一行，你看得出那段时间缺了数。
- 晨报里的用量一节也改成按积分算，和 `/hourness` 的面板同一个算法。
- GLM 登录失效时，`/glm-status` 那一段的第一行就写着，后面跟着 `/glm-login`。退出登录之后那里写「未登录」。
- 循环板上有一组「来自 GLM 通道包」的四条：高峰开始时提醒模型、看状态时读额度、额度快用完时告诉你、登录失效时提醒你。这四条只能看，不能改，也不能关。
- 高峰档位（无影响、少做、不做，默认少做）在规则页上。想改，跟主 Agent 说「高峰改成不做」，或在输入框打 `/rules peak 不做`；页面上没有按钮。

## 会自己发生的事

- 工作日 14 点到 18 点是高峰，GLM 按全价算积分，其余时间半价。每段高峰里，走 GLM 的会话在第一步收到一句提醒，说法跟着档位走：
  - 无影响，或者只装了 GLM 通道包、读不到档位：和今天的提醒一字不差，模型照常做。
  - 少做：同时至多开 1 个 GLM 子 agent；练习题、对照实验、大的审查这类可挪的重活不开始，由主 Agent 挪到 18 点以后，已经派出去的也算；必要的活和已经派给它的任务照做。
  - 不做：不派 GLM 子 agent，不起花 GLM 积分的脚本；子 agent 的调用被推迟时先停下，说清停在哪。
  - 哪一档的提醒都不叫主 Agent 停下，也不让模型换模型或换套餐。
- 主 Agent 不受高峰影响：三档里你都能随时跟它说话，它自己的工具调用也不排队。高峰只管它派出去的 GLM 子 agent 和花积分的脚本。
- 默认少做：高峰里，在 Kiro 里跑的练习题和对照实验会停下，说明 18 点以后再跑，加 `--wait` 就自己等到 18 点。改了通道之后的真网核对照常跑。
- 选了不做：练习题和真网核对都先停下，18 点以后再跑（加 `--wait` 就自己等）。选了无影响：都照常跑。
- 脚本和子 agent 调用的停下与排队，要等规则板整块上线才有真正的拦截；在那之前，提醒会按档位说话，但没有东西去挡。同时只开 1 个子 agent 的上限由派活那一块执行，它还没装上时，这一条只是提醒主 Agent。
- GLM 正在用的时候，至多每 15 分钟读一次额度；没人用 GLM 时一次都不读。
- 5 小时或每周额度用到 80%，或者照现在的速度一小时内会用完，主 Agent 在下一次回话里告诉你一句。每个额度周期只说一次。
- 登录被服务端拒绝时，主 Agent 告诉你运行 `/glm-login`。如果主 Agent 自己就跑在 GLM 上，它这时也回不了话，你会在 DSH 里直接看到请求失败。
- 读额度成没成功、额度用完、登录被拒、高峰提醒发了哪一档、练习题每次被放行还是被挡下，这几样数都由系统自己记下来，不靠模型报。

## 什么时候问你

不问。这一块没有要你定的事。额度快用完、登录失效这两句是告诉你，不用回答。

## 替你定了的方向

- 高峰提醒按档位换说法。少做和不做两档去掉「这只是告知、不要推迟工作」，换成这一档要谁做什么；无影响和只装 GLM 通道包时一字不改。提醒的原文归这一块，规则板只告诉它现在是哪一档（这是编排方定的分工，你可以推翻）。
- 不做档的提醒只说谁该做什么，不说「停下」。没选上一版那句「GLM 的活等到 18 点，系统会叫它接着做」：走 GLM 的主 Agent 读到会以为自己该停，而你要它随时回话。
- 同一份提醒给主 Agent 和子 agent 一起读，每一句写明说的是谁。没选分两份：规则板交出的档位里不带角色，加角色要改规则板的接口。
- 少做时，已经派出去的活照做，挪不挪由主 Agent 在派之前定。没选让做到一半的子 agent 自己停下，因为它不知道自己的活能不能挪，停在半截会白做。
- 子 agent 的上限，规则板交几个就写几个，现在是 1。没选写死 1：这个数归规则板和派活那一块，写死了会和实际执行的数对不上。
- 真网核对算「必要的活」，少做时照跑。没把它算重活，因为它挡着合入，花的积分也少。
- 练习题和真网核对在启动前的检查，一上来就真的挡，没有先试运行一段。没选先试运行：挡不挡是你选的档位决定的，不是这一块新加的判断，先试运行会让默认的少做在这两个脚本上晚几天才生效。代码里新加的检查通常先试运行，这里是例外。
- 额度快用完的门槛是 80% 或一小时内用完。没选用完才说，因为那时已经来不及把活挪开。
- 只在 GLM 正在用的时候读额度。没选定时读，因为没人用时也会发请求，服务端对频繁查询限速。读额度的请求照 ZCode 3.17.1 的样子发，失败了不重试。
- 额度和用量记录留在你的用户目录，因为它们是整个 GLM 账号的数，不属于某个项目；规则和档位在项目里，归规则板。
- 写一行记录说明 10 月 29 日删过 806 条，删掉那个文件就撤销。
- 循环板上的 GLM 条目由 GLM 通道包交出，编排层里不写 GLM 专属的东西。

## 交给别的模块的

- 规则板：档位的存放、少做和不做的排队、主 Agent 每步提醒里讲高峰的那一行，都归它。这一块只保证规则页、`/glm-status`、`/hourness` 和那一行里的「到几点」是同一个数。
- 派活那一块：少做里「同时只开 1 个 GLM 子 agent」由它在派活时执行。
- 循环板和执行那一块：18 点高峰结束时，少做和不做两档都由循环板上项目编排自己的一条叫醒闲着的主 Agent 去做挪开的活；高峰里主 Agent 只剩被挡着的活时，不算它卡住、不来问你，由执行那一块停住、到点接着推。这一块只告诉它们几点开始、几点结束。
- 指标记录：额度读取、登录被拒这类整个账号的事没有项目可归，记到哪里请指标记录那一块定。
- 上手页：讲高峰档位的那一句若写钟点，取这一块交出的时段说明。
- 对已放行的规则板和循环板，各有一条小请求，写在项目图上，自举之后办：请规则板记下「高峰提醒的新说法先于规则行默认开启」，告诉循环板「下一次高峰变化的计算已经在主干」。两条都不改它们的契约。

## 放行

① 放行 M6 用量与高峰的设计

背景：这份设计按你新定的**主 Agent 不受高峰影响**改过一遍，提醒的说法也对上了规则板实际交出的档位。

推荐：评审已过，**直接开工**，先改高峰提醒的说法，再做额度读取和面板。

疑问：最没把握的是**练习题一上来就真挡**，没先试运行，你想先试运行就说一声。

不做：不让高峰档位**管到主 Agent 自己**，三档里它都随时回话。
