# 记忆与经验：九件活「怎样算做完」的人话版

设计 0.6。这是 design.md 第 1.2 节那九件活的人话说法，意思不变，只换了词。你定过这些条件之后再改要你出手，所以放行时一起看。想改哪条，直接说「第几条改成……」，不用等下一轮；你改了哪条，就照你的原话写进项目图。逐条的完整字句在 design.md 第 1.2 节。

## 九件活

1. 记忆的存取（m5-1）：带你原话的偏好不会淡忘，没有原话的事实 14 天不用淡掉一半；项目事实必须写出处，像密钥的内容和跟已有条目太像的内容存不进；关于你的存用户级，其余存本项目，两个仓库各存各的；你说「忘掉这条」或打 `/memory forget`，任何一条都能删，agent 自己删不了偏好；旧的记忆文件第一次写入时迁过去，原文件改名留着；两个进程同时往同一份写，一条不丢。
2. 会话开局的召回（m5-2）：主 Agent 开局第一次请求带一份记忆索引，偏好在前，淡忘的不列，至多 200 行；压缩之后再带一次，其余时候不重复，系统提示词不变；子 agent 没有记忆工具，也看不到索引。
3. 给 GLM 的提示词里讲记忆的一段（m5-3）：改成 ZCode 3.17.1 的原句加最少的改动，逐字对照的检查通过，不是原文的部分只有设计里列出的几处；记忆工具不全就不出这一段，没有经验查询工具就不出提到它的那一句。
4. 从你的改动里学习（m5-4）：系统用真实的图引擎写出再读回的历史，数出你改字段、否决提议、对方案说「不行」或补充、重开已做完的事这几类，再加汇报长短的变动，按类分组；主 Agent 能用只读工具查，每七天至多收到一次提醒，没有新内容不提醒；落点只有规则提议会问你。
5. 汇报长短（m5-5）：你说「以后都说重点」，主 Agent 带你的原话存一条偏好，下一个会话的 GLM 汇报按它来，当前会话不变；没说要一直这样的不存；你说「恢复默认」就删掉，回到配置里的值。
6. 经验的存取（lessons-1）：一条经验写明情况、坑、解法、证据，全存本项目；交回的候选与已有经验相同就并入，与你删过的相同就丢弃，像密钥的拒收，其余等主 Agent 合并，提醒只给主 Agent；派活时简报带至多 5 条相关经验；任何 agent 包括 worker 都能查；子 agent 不能合并；你说「删掉这条经验」，主 Agent 带你的原话删，说「找回来」就恢复，不带原话的删不了。
7. 命令失败时的提醒与复发（lessons-2）：shell 命令失败、报错里有某条经验的片段时，下一次请求带这条经验的提醒，至多 2 条，同一会话里同一条只提醒一次；成功的命令从不触发；匹配出错不影响命令结果；同一条经验 28 天内在 3 个会话里命中，主 Agent 收到一次提醒，可以向你提规则；全程不拦任何动作。
8. 经验页（lessons-3）：页面列出本项目的经验和候选数，下半部分列偏好、推测、项目事实和汇报长短，每条下面一行「要改」；页面上没有按钮、开关和表单，源码里也不调用任何命令；记录文件有新内容后 15 秒内更新。
9. 第一批经验（lessons-4）：21 条都在本项目里，证据指向文档的行、提交和节点，重复导入不多出一条；查「PowerShell encoding」能查到 PowerShell 5.1 那一条；对写入范围 `docs/graph/**` 派活，简报里有「worker 写图」那一条。其中第 7 条（引号里的 `=>`、`>>>`、`->` 被当成重定向）按你 10 月 31 日定的「规则直接拦」写：解析认引号，启用那一行之前先把无害写法写进测试，不教新检查先走一段只记录、不拦的阶段。

合起来（记忆，m5）：桌面版上，在本仓库和另一个临时 git 文件夹各开一个 GLM 会话，记忆各写进各自的 `.llm`，索引出现，经验可查，桌面版日志没有本包的新错误。

合起来（经验，lessons）：九件都做完；周报里能看到每条经验命中的会话数，和经验存在之后同一报错又出现的会话数。

## 怎样改

最没把握的是推测的习惯（第 1 条）：系统从你的改动里猜出来的习惯不问你就记下，14 天不用就淡掉一半，你说一句「忘掉」就撤。你对这一条不放心，直接说，就改成先问你。
