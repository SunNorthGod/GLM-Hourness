# 记忆与经验：给你看的一页

这一块是两样东西。记忆：agent 记住你是谁、你要怎样干活。经验板块：这个项目踩过的坑和解法。
记忆已经有一个旧版本在跑，这次改成按项目分开存、事实要写出处；经验板块是新的。
完整设计在同目录的 `design.md`（0.5），这一页只讲你会碰到的部分。
这块不在自举必经的路上，实现排在 split 合入之后。

## 你会看到什么

- 项目面板首页的页脚多一个「经验 ›」，首页不为它多一行。经验行和记忆行都没装上时，页脚不显示它。
- 页面上半是经验。顶上一行「本项目 12 条经验 · 2 条候选等主 Agent 合并」。每条写坑是什么、怎么解、几天前确认过、近 28 天有几个会话碰到；情况（文件、命令、报错片段）作小标签，证据里的提交号和节点可以点开；灰字写它从哪来。页尾两节默认折起：「agent 收起的」「你删掉的」。
- 页面下半是记忆：
  - 「关于你」：偏好，每条带你的原话和时间；汇报长短单独一行。
  - 「agent 推测的（会淡忘）」：写还记得几成。
  - 「项目里的线索」：带出处和还记得几成；旧文件迁来的标「没有出处」。
- 页面上没有按钮、开关和表单，也不经任何命令写东西。每条下面一行：「要改：跟主 Agent 说「忘掉 <名字>」，或在输入框打 /memory forget <名字>」。
- 输入框有两个命令：`/lessons`（show、delete、restore、drop）和 `/memory`（show、forget、restore）。你敲的几个词会留在会话日志里。
- 记录文件有新内容后 15 秒内页面更新。

## 会自己发生的事

### 记忆

- 记忆分偏好和事实两种。带你原话的（或你在输入框亲手打命令存下的）「关于你」「你要怎样干活」是偏好，不会淡忘，只有你能撤。其余是事实：14 天不用就淡掉一半，被查到一次就加固一点，淡到几乎忘掉（约 47 天没用）的不再进索引，但还查得到。系统不自动删任何一条。
- 例如你说「先说结论，别堆术语」，主 Agent 带着这句原话存成偏好。它从你的改动里猜出来的习惯存成推测，会淡忘，你说一句「忘掉」就撤。
- 关于项目的事实必须写出处：项目图的节点、项目里的文件、提交号或网址，写不出就存不进。新条目跟已有条目太像，或内容像密钥，也会被拒并说明原因；深层路径、文件名、长标识符不受影响。
- 只有主 Agent 能写记忆。子 agent 没有记忆工具，也收不到索引；它们学到的东西写在交回里，由主 Agent 决定记不记。
- 会话开局，主 Agent 的第一次请求里带一份记忆索引：偏好在前，事实按记得多少排，淡忘的不列，至多 200 行。压缩对话之后再带一次，其余时候不重复，系统提示词不变，提示词缓存照常命中。开局时一条记忆都没有的会话，第一次存了东西后的下一步出现一次。
- 给 GLM 的提示词里讲记忆的那一段，从 883 字符改成约 2,210 字符：绝大部分是 ZCode 3.17.1 的原句，只做最少的改动，由逐字对照的检查核对。只有 GLM 的主 Agent 带这一段；记忆工具不全就不出。每个请求多约 1,300 字符，都在能命中缓存的前缀里。
- 存放：关于你本人的记忆存用户级目录，所有项目共用；项目事实和项目规范存本项目的 `.llm/`，不进 git（第一次写之前先把它加进 `.git/info/exclude`，加不进去就不写）。两个仓库各存各的，工作树里的会话存进主检出的 `.llm/`；不在 git 仓库里、又没有 `.llm/` 的文件夹不算项目，项目级记忆拒存并说明。旧的 `memory.json` 第一次写入时迁过去，原文件改名留着。
- 汇报长短（设计里叫汇报细度，三档：简洁、适中、详细）：你说「以后都说重点」「你每次都太长了」，主 Agent 判断是不是要一直这样，是的话带你的原话存一条汇报长短偏好。下一个会话的 GLM 汇报按这一档，当前会话不变。只是这次嫌长，不存。你说「汇报细度恢复默认」就删掉。先后：你最近一次说的，其次配置里的值，最后是适中。
- 删除和恢复：你对主 Agent 说「忘掉这条」，它带你的原话删，偏好也删得掉；或者在输入框打 `/memory forget`。删除不抹文件，留着删之前的样子，`/memory restore` 能找回。

### 从纠正里学习

- 系统从项目图的历史里数你纠正过什么：你改了 agent 写的字段、你否决了提议、你在对话里对方案说「不行」或补充、你重开了已做完的事。另加汇报长短的变动，和（M7 合入之后才有）主干上不是派活合入的提交改了 agent 刚合入的文件。按类分组，同样的输入得到同样的结果。你让主 Agent 改的字段，它带着你的原话写；你对方案说的「不行」和补充，它记成固定开头的批注。系统按这两种写法认，不靠猜。
- 主 Agent 有一个只读工具 `learning_signals`，列出每组出现几次、哪些已经落了点、落点之后又出现几次，附最近 4 周每周的次数。有新内容、距上次提醒满 7 天时，主 Agent 收到一条提醒去看，每七天至多一次。这条路不等 M7 的周报。
- 每个至少出现 2 次、还没落点的组，主 Agent 选一个落点并把组名记在上面：偏好、推测、经验、规则提议、候选练习题。只有规则提议会交给你，走规则板和主 Agent 的四行方案；其余不问你。
- 落点之后同类再出现的次数按周看走向。次数不降，主 Agent 下一轮换个落点，例如把经验升成规则提议。

### 经验

- 一条经验写：什么情况下（文件、工具、命令、报错片段，至少一项）、踩了什么坑、怎么解、证据（至少一条）、最近一次确认。都属于本项目，包括通用的坑；新项目要把这些坑重新学一遍，这个代价你已经知道。
- 例如：批量缩图工具一次打开全部原图，文件夹超过约 1000 张就报「打开文件太多」。解法是加 `--chunk 200` 分批跑，并数一数输出，因为被跳过的文件它也返回成功。
- 来源是 worker 交回里附的候选。与已有经验完全相同的并入，确认数加一；与你删过的相同的丢弃，只记一次「删后复发」；像密钥的拒收；其余成为候选，等主 Agent 合并。主 Agent 自己踩的坑直接写。候选放 30 天没人处理就过期，可以重开。
- 有候选等着时，只有主 Agent 的会话收到提醒，列至多 5 条，列表变了才再提醒；你随手开的普通会话收不到。主 Agent 那一块还没装上、认不出谁是主 Agent 时，任何根会话都算。
- 三种用处：
  - 派活时，M7 把相关的经验（至多 5 条）放进 worker 的简报；只因为用了某个工具才匹配上的不放。
  - 命令失败时：shell 命令退出码非 0，报错里有某条经验的片段，下一次请求带上这条经验的提醒（至多 2 条，同一会话里同一条只提醒一次）。成功的命令从不触发，匹配出错也不影响命令结果。
  - 所有 agent 包括 worker 都能用 `lessons_query` 查。
- 经验只是建议。经验行和记忆行都不拦任何动作，提醒和查询结果里都写「advice, not a rule」。同一条经验 28 天内在 3 个会话里命中，主 Agent 收到一次提醒，由它判断要不要用规则提议和四行方案向你提规则；每个项目每周至多 2 条。你删掉过的经验不再提醒。
- 删除和恢复：你对主 Agent 说「删掉这条经验」，它带你的原话删；说「找回来」就恢复；不带原话的删不了。也可以在输入框打 `/lessons delete <编号>`。删除同样不抹文件。
- 第一批 21 条经验来自 `DEVELOPMENT.md` §5 和 §7、`HANDOFF.md` §6、2026-10-29 的两次事故（worker 不顾简报写了图；简报写在你拍板之前而过时）和蓝屏清零状态文件那一次。第 7 条里「新的合入前检查先试运行」保留：它说的是写在代码里的检查，在 CHARTER 0.7 下仍然成立。
- 给晨报、周报、巡检的数：经验新增、并入、丢弃、过期、被你删和恢复的条数，候选数，每条经验命中几个会话，经验存在之后同一报错又出现在几个会话。只看走向，不设达标线。巡检另列出处已被取代的事实、180 天没确认的经验、放了超过 7 天的候选和相似的经验。
- 练习题（固定的小项目，系统自己跑，查一次改动有没有改坏东西）运行时读不到真实的记忆和经验，免得同一道题随经验增多拿到不同的上下文。

## 替你定了的方向

- 记忆和经验分成两份记录，不并成一份再加类型字段。没选并成一份：两者读法不同（记忆开局给索引，经验按文件、命令和报错匹配），一套工具同时教两件事，模型分不清往哪写。底层的读写、锁和留痕共用一套，崩溃恢复不用写两遍。
- 项目事实要写出处（可推翻）。没选只存偏好：要改掉 ZCode 的原句，agent 想记的事实每条多一次写图。没选照旧不写出处：事实在记忆、图和文档里各有一份，记忆里那份会过时，现在仅有的一条就是 10-27 的过时交接。
- 记忆索引放在对话里，不放进系统提示词。没选做成提示词的一节：要按会话把内容冻在内存里，重启后算出不同内容，缓存会失效一次。
- 汇报长短由主 Agent 判断后写，不由系统按词表判。没选系统监听你的话：自然语言的词表会误判。没选每次说都写：一次性的抱怨会改掉之后每个会话的默认。
- 汇报长短取你最近一次说的，不做平滑。你一眼看懂，说一句就回去。
- 记忆的几节放在经验页下半部分，不另设一块。面板页脚只有规则板、循环板、经验三块，多一块要改面板的设计。
- 经验页只看不点，删除在对话里说或在输入框打命令（你定的）。
- 经验没有范围字段，全在本项目；用户级目录里只有关于你本人的记忆。
- 项目根和文件锁沿用仓库里已有的两个模块，不另写第二份（`m5` 节点上的裁定）。
- 不碰你 profile 里记忆行的 `home` 设置：行忽略它，并在状态里说一句。
- 不做语义检索（向量）：ZCode 的语义召回默认关，条目少，关键词匹配够用。
- 推测出的习惯不问你就记，会淡忘，你说一句就撤。你对这一条不放心，见下面放行的第一项。

## 放行

① 记忆与经验九件活怎样算做完

背景：记忆与经验拆成**九件活**，上面已经用人话写了每件做完的条件。

推荐：你**逐条看过、改完**，再写进项目图开工。

疑问：最没把握的是**推测的习惯**：不问你就记下，14 天不用就淡忘，你一句话就能撤。

不做：不把九张单子**直接写进项目图**，开发流程那十张你也是逐条看过的。
