## Observations that are not blockers

1. An error fragment is length-checked before it is normalised (`CATEGORY_RULES.errors`), and matched after (`longestFragment`, `normalizeFailure`). A fragment that is mostly ANSI codes passes the 8-character check and then normalises to a short word: `checkSituation({errors: [ESC + '[31merror' + ESC + '[0m']})` is accepted, and `matchFailure` then matches any failure that contains `error`. That is the case the 8-character rule of 4.4 step 3 exists to prevent. It needs a writer to put escape sequences into a fragment, so it is not a likely path; when S7 wires `lessons_merge`, checking the length of the fragment as `normalizeFailure` sees it would close it.
2. `proposeRecords` takes `evidence` as given. `candidateEvidence` can return an empty list when even `context.session` is not an id of the 5.7 form (the spec asserts that case), and a `propose` record without evidence is a bad line in the fold. S7's `propose` should run the planned records through `judgeRecord` (the progress notes already say so) and answer `{error}` instead of writing a record the fold drops.
3. The `reopen` hint (`the user restores it: quote their words in relay and use action restore`) is the design's text; for a candidate that carries `deletedMatch` the working way is `reopen` with `relay`, not `restore`. S7's tool text can say so for that case.
