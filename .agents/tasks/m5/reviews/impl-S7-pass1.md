## Observations that are not blockers

1. A note on the graph with no JSON object at its end is refused as `invalid` and recorded, where design 4.2 step 2 says the whole sentence becomes the pitfall. The design text cannot hold together with the rule that a candidate has at least one situation item; the code chooses the rule, says so in `candidateOf`'s comment and the progress notes, and `hygiene` lists the refused note. M7's fallback always writes the JSON (design 8.1 item 3), so the normal path is unaffected.
2. The `user_only` hint for `reopen` says to use action `restore`, which takes a lesson; for a candidate dropped for matching a deleted lesson the working way is `reopen` with `relay` (S3 review item 3). The text is the design's; `MERGE_DESCRIPTION` does not say it either. A model that follows the hint gets an `invalid` for the field `candidate`. Reachable only after the person deleted a lesson and the same candidate came back.
3. S3 review item 1 (a fragment that is mostly ANSI codes passes the 8-character write check and normalises to a short word) is still open. The write check in `lessons_merge`, the CLI and `propose` does not measure the normalised length. It needs escape sequences in the fragment; S8's failure matching is where a too-short fragment would produce noise (two advisory reminders at most, once per session per lesson), so S8 can close it with one length check.
4. `propose` writes `by.session` as the dispatching session (`context.session`), not the worker's `childId`. For a candidate merged into a lesson through `propose`, the recurrence count therefore sees the dispatching session. Nothing reaches this path until M7's handback processing exists; when it does, whether the worker session or the dispatching one should count for the "three sessions" rule is a question for the M7 integration and for S8.
5. `notes` of `propose` for `scope: "all"` are English text (`scope "all" is not used: …`) where the acceptance line quotes the Chinese phrase. The notes go into a handback summary that a model reads, and design 4.1 says text for models is English; the spec pins the English text.
6. The commit holds the row and four small extractions (`row-support.ts`, `secretRefusal`, `read-stdin.ts`, `tests/row-host.ts`). The plan asks for one concern per commit, but each extraction exists because the row would otherwise add jscpd clones, and the message names them and why.
7. Cosmetic: `tests/memory-helpers.ts` has "Run a tool of a table as gent" in the new `runTool` comment; `docs/DEVELOPMENT.md` now ends without a final newline.
