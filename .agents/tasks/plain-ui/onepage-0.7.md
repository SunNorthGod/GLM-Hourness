# 面板说人话与新手引导：一页说明

设计 0.7（2026-10-30）。0.6 经第 6 轮评审通过；0.7 在它上面加了两层循环在面板上的样子（你定了用户的项目也按两层循环走），并改了评审留下的 6 处小问题。全文在同目录 `design.md`；样子见同目录的草图：`mockup-home.svg`（首页）、`mockup-modules.svg`（框架与模块，新）、`mockup-onboarding.svg`（开场画面与上手页）、`mockup-boards.svg`（规则板与循环板）、`mockup-drilldown.svg`（一件事的页面）、`mockup-plan.svg`（计划）。

## 你会看到什么

- 项目图面板打开是一页首页，没有页签。从上到下五节：效果是（每个目标做完几件、还剩几件）；需要你（在等你回话的事）；现在（谁在做哪件事，GLM 高峰时多一行「GLM 高峰中，到 18:00 · 高峰模式：少做」）；怎么做（接下来的三件）；上次看之后（你上次离开面板以后变了什么，包括「你在对话里同意了……」这类）。
- 每一项都能点「讲细点」展开、「说重点」收起，只改显示。点进一件事是它自己的一页，最后一节是「底账」：编号、类型、历史、证据这些 agent 的工作记录，追问「凭什么」时再看。首页上不出现路线编号、内部代号和代码名。
- 「需要你」里每件事照你定的样子：题目一段，背景、推荐、疑问、不做各一行，每行重点几个字加粗。没有选项、字母、推荐标签，也没有批准、拒绝按钮。每件下面一行「去主 Agent 的对话回话 ›」，点了打开那个对话；你就在主 Agent 的对话里时写「在这个对话里回话」；还没有主 Agent 时写「在输入框打 /wish」。
- 项目按两层循环走时（访谈之后你和主 Agent 先定框架、分成哪几块、哪些方向不能变）：
  - 首页「效果是」里，分了模块的目标下面多一行，例「6 个模块：1 个等你放行 · 2 个在开发 · 2 个设计中 · 1 个做完了 ›」。
  - 点开是「框架与模块」一页：先是框架（定了，或「在改」）；再是模块清单，按当初定的先后排，每块写它走到哪了：设计中、等你放行、放行了、在开发（做完几件、还剩几件）、做完了；最后是方向清单，你定过的每一条照原文列出，下面一句「要改：跟主 Agent 说「方向清单加一条……」」。页上没有任何按钮。
  - 一块的设计等你放行时，它也出现在「需要你」里：「主 Agent 在对话里等你放行「循环板」」，下面是那四行，再下面「去主 Agent 的对话回话 ›」。那一页放行稿在主 Agent 的对话里看。
  - 图上还没有方向清单时这些都不出现，所以这个仓库今天的面板上看不到它们。
- 首页最下面一行入口：规则板、循环板、经验、整张图、上手说明。
  - 规则板：你定下的规矩；插件带来的默认规则（GLM 高峰按全价计积分）与高峰模式此刻的档位；两道会拦住动作的门，就是合入前要跑的检查清单和必须全审的那张清单，逐条原文列出；写在代码里的规则。
  - 循环板：碰到某件事就做的（改完文件就跑的检查器、合入主干后跑一遍完整检查等）；到点做的（晨报、周报、夜间巡检）；你自己加的（例如每周读文章、服务器巡查）。
  - 插件带来的条目都标「<插件>带来的 · 只能看」，没有开关，也删不掉。你能改的地方下面一句「要改：跟主 Agent 说「……」，或在输入框打 ……」。
- 引导，两个插件各管各的：
  - GLM：新会话的开场画面上，工作区那一行右边有「GLM · 上手」，会话里输入框下方的 GLM 按钮也写「GLM · 上手」。点开是三步：登录、在模型选择器里选 GLM 的模型、发一句话。没登录就发消息时，先给一句中文「还没登录 GLM：点输入框下方的 GLM 按钮登录」。
  - 项目图：第一次打开是上手页，六块：一眼看懂；你要做的只有回话；让主 Agent 接手（打 /wish；它先问清楚，再和你定框架、分几块、哪些方向不能变，每一块的设计你同意了才开工；提醒「主 Agent 用强一点的模型」）；规则板与高峰模式；循环板；去哪看进度。底部一个「去首页」，跳过也点它。
  - 上手页的高峰模式一段：三档无影响、少做、不做，默认少做。少做是高峰时少派活，练习题、对照实验、大的评审这类重活挪到高峰之后，必要的照做。要改就跟主 Agent 说「高峰改成不做」，或打 `/rules peak 不做`；下面一行写此刻是哪一档，那一刻读不到是不是高峰时写读不到的原因，这段照样讲。只装编排层、没装 GLM 包时这段不出现。
  - 开场卡片底部一行「第一次用？看看项目图怎么用 ›」。没有项目图的工作区换成一张卡片「这个工作区还没有项目图」，有接管命令时带「建一张项目图」按钮。

## 自己会发生的事

- 面板跟着项目图自己变。你在对话里回过话、主 Agent 记下之后，那件事从「需要你」里消失；主 Agent 改了方案再提，它带着新的一版回来。
- 模块的状态也是从图上算的：你在对话里放行一块之后，它变成「放行了」，开始派活就是「在开发」。开发中碰到问题分三档：只影响这一块、改得回来的，主 Agent 自己定，「上次看之后」里写「agent 自己定了……」；要改这一块的设计方向的，这一块回到「设计中」，改好再交给你放行；要改框架的，框架那一行写「在改」，受影响的活先停着。哪些活停了面板不逐个标，问主 Agent。
- 「上次看之后」从你上次离开面板算起；面板连续看了 5 秒以上才算看过，离开不到 10 分钟回来不算新的一次。
- 上手页只自动出现一次。GLM 上手读到已登录就收起；你没点过它，它在 3 个新会话里出现过之后也自己收起。没图的卡片每个工作区一次。不弹窗，不弹提示，不自动拉开右侧栏，不往对话里写东西。
- 高峰时规则板照档位执行，出厂是少做。方案你放行以后，主 Agent 自己推进到做完；晨报、周报到点由系统提醒主 Agent，在它的对话里写给你。
- agent 写给你看的标题和说明会被自动检查：编号、代码名、没解释的行话（验收、门禁、投影之类）、太长、要你定的题缺背景。先只提醒 agent；现有的写法都改好、每个会向你提问的工具都验证过以后，再改成直接退回。

## 什么时候问你

- 要你定的事都在主 Agent 的对话里问，每件四行，一次至多三件。你说「可以」、补一句，或说「不行，因为……」；随口说的它会先复述一遍再记。面板上不用点任何东西。
- 两层循环里，每一块开工前都会来问你一次放行，也是在主 Agent 的对话里，四行加一页放行稿；框架、模块清单和方向清单要改时同样来问你。
- 实施时会来问你一次：现在还开着的 80 件事，标题统一改成人话。agent 列一张新旧对照表交给你，你同意、补充或否掉。
- 实机检查要测「只装一个插件」，得临时关掉另一个插件的一行，会先问你，测完恢复。
- 你想改高峰档位、加或删自己的循环任务，就开口说；主 Agent 写成四行给你确认后才记下。
- 主 Agent 万一忘了记你的回话，那件事会一直挂在「需要你」里，跟它说「记下来」就好。
- 这一稿现在只有一件要你定：

① 这两件事怎样算做完

背景：面板和新手引导共 17 条「怎样算做完」，写进节点后**再改要你出手**

推荐：**放进一页放行稿**，你放行时一起看

疑问：你要是**想逐条改**，就得先给人话版，晚一轮开工

不做：**照方案原样写入**：上次派活那块你选了自己看

（17 条在 `design.md` §1.4，第 17 条是这一稿为框架与模块加的。「上次派活那块」是派活给子 agent 的那十件活，你当时改成逐条看过再定。）

## 替你定了、你随时能推翻的

1. 面板只看不能点，改高峰档位也是说一句或打 `/rules peak`。这一条最可能不合你意：你说过「档位当然能选」。如果你想在面板上点，就只给档位留三个按钮，作为面板上唯一能写东西的地方。
2. 删掉只给面板用的写图命令 `/graph-apply`，面板不写之后没人用它。`/graph-run`（开始、暂停、重做一个任务）留着给你自己打。
3. 以前在面板上点过的人，升级后不自动弹上手页，判断依据是图上有没有你本人操作的记录。这个仓库的图上有 21 条，所以你在这里要从页脚「上手说明」打开。新用户接管项目、第一次 /wish 留下的记录不挡它。
4. 要你定的题带一行背景，至多 60 个字。
5. 开着的 80 件一次改完，已关的不改。
6. 主 Agent 问需求、出方案期间顺带提出的那一批小事，不在「需要你」里逐条列，随「确认需求」「放行方案」一次定。
7. 你原样同意、补充、否掉的比例不在面板上显示，进周报。
8. 不是主 Agent 的对话里，面板把那里的 agent 叫「这个对话的 agent」，主 Agent 只有一个。
9. 子 agent 用什么模型由主 Agent 选；引导里只提醒「主 Agent 用强一点的模型」，不再说「子 agent 用便宜的就行」。
10. 面板上的「讲细点」「说重点」只是展开收起，不改主 Agent 平时跟你说话的详略。
11. 模块的样子放在首页「效果是」每个目标下的一行，加一页「框架与模块」，首页不另开一节。代价：首页只看得到各状态几个，看哪一块要点进去。
12. 「框架与模块」页上模块按当初定清单的先后排，状态变了位置不动；等你放行的那一块同时在「需要你」里。
13. 图上有了方向清单，面板才显示框架与模块。这个仓库的图上有两个旧的带阶段的特性，只按「带阶段」认会把它们误认成模块；方向清单是先定框架那一步留下的，有它才说明这个项目在走两层循环。

评审留下的 6 处小问题这一稿都改了，都是逐处改字，不动已经过审的做法。你看得见的两处：那一刻读不到是不是高峰时，上手页照样讲高峰模式，「现在是」一行写读不到的原因（规则板要多交一个「装没装 GLM 包」的信号）；规则板和循环板草图上高峰那两条的来源改成了「项目编排带来的」，高峰时刻取自 GLM 通道。

面板只显示两层循环，不管它怎么转：每一块的放行由主 Agent 的放行那一部分做，开发中的三档与攒成批由派活那一部分做。面板读的图上的样子（方向清单是哪个节点、哪些算模块、一块的放行在对话里怎样标出是哪一块）写成了给那两部分的要求，它们定稿时要是写法不同，面板跟着改。
