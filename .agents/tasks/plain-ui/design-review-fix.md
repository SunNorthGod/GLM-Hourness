## 3. 新发现

### P12-01（MEDIUM）板没有给 `held` 时，页面照样写「乘 3」「X 秒的 3 倍」，数与来源对不上时不出声

位置：§4.7「数与来源」第 1、2 种与末段的形状错误清单；§8.2 超时一格；§10.1 的 1.0 一条；§10.3 第 13 项 (b)；§11 第 2、4 条；§14 第 37 条。

问题：1.3 的规则是「被截住时板带 `held`，没有 `held` 才写『乘 3』或『X 秒的 3 倍』」。面板不核对超时的数 V 是否真等于 3×E 或 3×X：§8.2 只在 `held` 在的时候查「Y 与超时的数对不上」，`held` 不在时什么都不查，也没有 `console.warn`。设计自己在 §11 第 4 条与 §14 第 37 条写明，M4 的 `ValueLine` 现在没有与 `capped` 对称的下限标记，要 M4 加上「使循环板能给面板 `held.by: 'floor'`」；循环板 0.6 按 `d-freeze-until-dogfood` 自举之后才改。所以唯一有下限的那块（M4 的检查）在过渡期里最可能的数据是：`measured`、X = 1、V = 5、没有 `held`。页面会写「系统按最近 10 次最慢的 1 秒的 3 倍定」，正是 P11-01 指出的那句错话，而且没有任何信号。一页稿第 8 条对人承诺「数据缺了或对不上，那一格写『没有记录』和原因，不留白」，这一情形落空，属于「失败而不出声」。面板手里有 V、E、X 三个数，核对不需要知道任何一块板的下限或上限，也不违反「面板不写死」。

另外 §11 第 4 条「使循环板能给」的前提不完全对：M4 现稿的 `ValueLine.source` 在 `harness` 一种带 `runs`、`factor`、`floorMs`，在 `estimate` 一种带 `estimateS`，再加上 `limitMs`，循环板今天就能算出被下限抬高（`factor × max(runs) < limitMs`，或 `3 × estimateS < limitMs`）。上一轮修法第 3 点也是按这个读法写的（「M4 的检查由板按 `ValueLine.source.harness.floorMs` 给」）。

修法：
1. §8.2 超时一格加一条形状规则：「`agent-estimate` 与 `measured` 不带 `held` 时，超时的数要等于 3×E 或 3×X（按板给的原数比较，板不先取整；差不超过 0.5 秒算相等）；不相等时来源那一句写『没有记录：超时的数和来源对不上（<V> 秒，3 倍是 <3X> 秒）』，`console.warn` 每个条目一次，条目其余部分照常。」§4.7「数与来源」末段的形状错误清单加「没有 `held` 而超时的数不是 3 倍」。
2. §10.1 加四例：`measured` X = 1、V = 5、没有 `held`：写「没有记录：……对不上」，不含「1 秒的 3 倍定」，警告一次；`agent-estimate` E = 1、V = 5、没有 `held`：同上；`measured` X = 4、V = 12、没有 `held`：照常；`measured` X = 1.4、V = 4.2：照常（不因舍入误报）。
3. §11 第 2 条改写：M4 加上下限标记之前，循环板按 M4 取值行里的数自己算 `held`（`harness`：`factor × max(runs)` 与 `limitMs` 比；`estimate`：`3 × estimateS` 与 `limitMs` 比；`capped` 直接对应 `by: 'cap'`，`wantedS` 取 `capped.wantedMs / 1000`）。§11 第 4 条与 §14 第 37 条保留给 M4 的请求，把「使循环板能给」改成「免得循环板自己算」。
4. §10.3 第 13 项 (b) 的下限核对加前提：「循环板按 §11 第 2 条给出 `held` 之后再核对下限句；在那之前，这一条应写第 1 步的『对不上』一句，不应写『1 秒的 3 倍定』。」

### P12-02（MEDIUM）主 Agent 调高的上限在页面数据里没有位置，一页稿把 M4 的范围写成固定的 5 秒到 60 秒

位置：§4.7「数怎样定」；§8.2 超时一格；§1.4 第 8 条 (c)；`onepage-done.md` 第 8 条「例如改完文件就跑的检查是 5 秒到 60 秒」；§11 第 2、4 条。

问题：`d-timeout-measured` 12:56Z 的细化裁定写「实测的 3 倍超过上限时只告诉主 Agent，由它自己处理（拆小或收窄检查，或把上限当作可撤回的设置调高并写明理由）」。M4 0.6 §6.3.1 把它落成工具 `check_limit`：61 到 600 秒，理由过 `plainWordsIn`，记在 `limits.jsonl`，`ValueLine.cap` 为 `{by: 'setting', capS, at, reason}`；并写明「循环板页的明细与晨报……都写出『上限已调高到 <n> 秒：<理由>』，所以人能看见、能说一句话撤回」。面板 1.3 说把超时的说法写全了，全文却搜不到 `check_limit`、调高、`limits.jsonl` 或「上限已调高」，§8.2 的超时数据也没有放调高后的上限与理由的字段。调高之后，页面会写「超时 75 秒（系统按最近 10 次最慢的 25 秒的 3 倍定）」或「超过上限，保持上限 120 秒，已告诉主 Agent」，而人在一页稿里读到的是 5 秒到 60 秒，看不到是谁调的、为什么、怎样改回。这是主 Agent 替人做的一个可撤回的决定。`d-timeout-measured` 要每个超时值的来源看得见，M4 也把「人能撤回」押在页面显示上，面板的数据形状是这一环上唯一缺的一块。

修法：
1. §8.2 超时一格加可选项 `capRaised: {capS, at, reason}`（`capS` 为正数秒，`at` 为时刻，`reason` 为非空的一行）。它对 `agent-estimate`、`measured`、`ceiling` 三种有效，`ceiling` 的超时的数这时就是调高后的上限。带在 `fixed-by-design` 上或形状不对时写「没有记录：<原因>」并告警；不带时什么都不显示。面板不写死 600 秒，也不核对 `capS` 的范围。
2. §4.7「数怎样定」在 M4 那一句后面加：「M4 每项检查的上限可以由主 Agent 调高（M4 0.6 §6.3.1 的 `check_limit`），调到几秒和理由由板给。」页面在超时那一句下面多一行：「上限已由主 Agent 调高到 <capS> 秒 · <日期>：<reason>；要改回，跟主 Agent 说」。晨报用同样的字（面板只定字，§11）。
3. `onepage-done.md` 第 8 条在「例如改完文件就跑的检查是 5 秒到 60 秒」后面加半句：「主 Agent 可以为某一项把上限调高，页面写明调到几秒、为什么，你说一句就能改回」。§1.4 第 8 条 (c) 加同样的半句。
4. §11 第 2 条加「`ValueLine.cap.by` 为 `setting` 时交 `capRaised`」。§10.1 加两例：`measured` 带 `capRaised` 时写那一行；`capRaised` 带在 `fixed-by-design` 上时写「没有记录」并告警。

### P12-04（NIT）没写估计时起点的来源怎样标，只写了拦路脚本与 M4

位置：§4.7「数怎样定」与第 4 种「采纳之后，没写估计的拦路脚本起点用的缺省 10 秒……」；§12 第 53 条；§11 第 2、3 条。

问题：`d-timeout-measured` 也管循环板上不拦路的脚本与 M7 合入前的检查。循环板 0.6 §6.6 给不拦路的脚本缺省 60 秒、封顶 1800 秒（`timeoutSeconds` 取 5 到 1800），§4.7 第 4 种列了这两个数，「数怎样定」的下限与上限一段却没有列它，「没有估计时的起点」也只写了 M4 的检查（`ceiling`）与拦路脚本（`fixed-by-design`）。循环板与 M7 采纳时，没写估计的条目该给 `ceiling` 还是 `fixed-by-design`，要实现者自己推。

## 第二遍 3. 新发现

### P13-01（MEDIUM）`capRaised` 取自 `ValueLine.cap`，而 M4 只在超时的数变化时写 `ValueLine`：撤回之后页面仍写「已调高」，调高之后可能一直不显示

问题：M4 0.6 §6.3.1「可追溯」写「每次取值变化写一条 `ValueLine`」。`ValueLine.cap` 的注释是「The maximum that applied」，记的是写这一行时生效的上限。一项检查现在的设置以 `limits.jsonl` 里它的最后一行为准（同节「调高上限」末段；§10 输入校验表 `limits.jsonl` 一行）。`check_limit` 的 `raise` 与 `reset` 只写 `limits.jsonl`，M4 没有写明它们会补一条 `ValueLine`。所以最新一条 `ValueLine.cap` 会与现在的设置不一致，有两种情形：

1. 撤回之后仍显示调高。某项检查调高到 120 秒，之后慢的那几次滑出最近 10 次，数降到 45 秒；这一行 `ValueLine` 仍带 `cap: {by: 'setting', capS: 120, …}`。人照页面说「改回」，主 Agent 调 `reset`，上限回到 60 秒，数仍是 45 秒。没有取值变化，就没有新的 `ValueLine`。页面继续写「上限已由主 Agent 调高到 120 秒 · …；要改回，跟主 Agent 说」；人再说一次，`reset` 返回 `noop`。这种状态一直留到数再变化，期间没有任何信号。
2. 调高之后不显示。`check_limit` 第 4 步也允许按「最近 7 天内有一条 `timeout` 的 `limitMs` 等于当前上限」调高。那次超时滑出最近 10 次之后，数可能已经降到 60 秒以下（例如 45 秒），调高到 120 秒不改变数，就没有新的 `ValueLine`，页面没有调高那一行。即使数会变，也要等下一次运行重算后才写，`check_limit` 返回到下一次运行之间页面同样没有这一行。

P12-02 要补的就是「人能看见、能说一句话撤回」这一环，这里页面失真而不出声，属于「失败而不出声」。§10.3 第 13 项 (b) 的走查拿一项被截住的检查先调高、再 `reset`，数在 60 秒以上来回变，两次都会有新的 `ValueLine`，所以这条走查查不出上面两种情形。

修法：
1. §11 第 2 条把 `capRaised` 的来源改成 M4 现在生效的设置：「`capRaised` 取 `limits.jsonl` 里这一项的最后一行：`action` 为 `raise` 时交 `{capS, at, reason}`，为 `reset` 或没有这一项时不交；不取 `ValueLine.cap`（它只在数变化时写，记的是写那一行时的上限）。」§14 第 38 条同改。
2. §11 第 4 条给 M4 加一句，§14 第 37 条同加：「循环板页的明细与晨报里『上限已调高』那一句同样按 `limits.jsonl` 的最后一行写；也可以让 `check_limit` 每次 `raise`、`reset` 成功后补写一条 `ValueLine`（数不变也写）。取哪一种由 M4 定。」M4 0.6 §6.3.1「调高写在 `value` 记录的来源里……循环板页的明细与晨报……都写出」有同样的时差。
3. §10.3 第 13 项 (b) 的走查改成：调 `check_limit` 之后不触发检查，直接读 DOM，核对那一行已经出现；`reset` 之后同样不触发检查，直接读 DOM，核对那一行已经消失。按 `ValueLine` 取数时这两步都会失败，按设置取数时都会通过。

### P13-02（NIT）「晨报用同样的字」没有对应的请求

位置：§4.7「数怎样定」里「晨报用同样的字（面板只定字，§11）」；§11 第 4 条；§14 第 37 条。

问题：晨报「检查的超时」一节由 M4 写（M4 0.6 §6.3.1「看得见」一条、§3.10，写法是「上限被调高的写理由」）。§11 第 4 条只请 M4 去掉 `details` 里的超时半句，没有请晨报用 §4.7 那一行的字。§4.7 引的 §11 里没有这一条，读的人会以为晨报的字已经对齐了。

修法：§11 第 4 条加一句「晨报『检查的超时』一节里上限被调高的那一句，用 §4.7 的字：『上限已由主 Agent 调高到 <秒数> 秒 · <日期>：<理由>；要改回，跟主 Agent 说』」，§14 第 37 条同加。也可以把 §4.7 那半句改成「晨报的字归 M4（§11 第 4 条）」。

### P13-03（NIT）带 `held` 而 Y 不是 3 倍时，「对不上」一句把 Y 叫作「超时的数」

位置：§8.2 超时一格的不合法处理（「W 是……带 `held` 时是 Y」）；§4.7「数与来源」开头；§10.1「`held` 为 `{by: 'floor', wantedS: 4}` 而最慢 1 秒」一例。

问题：这一例页面会写「超时 5 秒（没有记录：超时的数和来源对不上（4 秒，3 倍是 3 秒））」。括号里的 4 秒不是页面上写的超时 5 秒，读的人对不上这两个数。

修法：带 `held` 时换一句：「没有记录：算出来的数和来源对不上（算出来是 <Y> 秒，3 倍是 <3B> 秒）」；没有 `held` 时照旧。§10.1 那一例断言这一句。

### P13-04（NIT）面板要求 `capRaised.reason` 是一行，M4 的 `reason` 没有这条限制；不合格时整行变成「没有记录」

位置：§8.2 的 `capRaised`（「`reason` 为非空的一行」，形状不对时「调高那一行写『没有记录：<原因>』」）；§10.1 里 `reason` 为空或多行的一例；M4 0.6 §6.3.1 `check_limit` 参数表（`reason` 1 到 300 字符、过 `plainWordsIn`，没有不许换行的规定）。

问题：主 Agent 写的理由里有一个换行时，M4 照收，面板却把整行换成「没有记录：……」。人看不到调到几秒，也看不到「要改回，跟主 Agent 说」。这时有告警，所以不是静默失败，但这一行要给人的两样东西都没了。

修法：建议 (a)，两者也可同取。(a) 只有 `reason` 不合格时，那一行照写「上限已由主 Agent 调高到 <capS> 秒 · <日期>（理由没有记录：<原因>）；要改回，跟主 Agent 说」，`console.warn` 一次；只有 `capS` 或 `at` 不合格时，整行才写「没有记录」。(b) §11 第 4 条请 M4 的 `reason` 不收换行（返回 `invalid`）。
