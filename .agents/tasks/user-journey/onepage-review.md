## Findings

### 1. NIT：「11 个方向」一行与正文里另标的两条「编排方定的」不是同一批

位置：`onepage.md`「对你有什么变化」第 3 条与第 5 条各带「编排方定的，你可以推翻」，「替你定的方向」一行写 11 个、列在第 6.2 节。

`journey.md` §6.2 只列接缝裁定，共 11 件。第 3 条的「撤下只有一条路」是 `d-one-lift-path`，第 5 条的「超时取估计的 3 倍、不取估计本身」是 `d-timeout-measured` 2026-10-31T08:17Z 的裁定。这两条在 `journey.md` S7 与 §7 方向清单的行文里写着，不在 §6.2 里。按页面自己的标注，人替他定的有 13 件，一行里只数了 11，人翻到第 6.2 节找不到后两条。

页面没有说错，也不影响放行这一问，所以是 NIT。

修法：把一行改成「编排方替你定了 11 个方向，列在用户图设计稿第 6.2 节；上面标了「编排方定的」的 2 条另见第 7 节。你都可以推翻。」或者把这两条补进 `journey.md` §6.2 再改数。

### 2. NIT：超时那一条漏了「不超过最长值」

位置：「对你有什么变化」第 5 条，「超时是这个估计的 3 倍」「超时仍是它的 3 倍」。

`journey.md` S7「超时怎么定」与 `d-timeout-measured`：3 倍超过最长值时保持最长值，并告诉主 Agent，由它处理，不来问人。页面按字面读，3 倍永远成立，被最长值截住的情形不成立。页面只用了 686 个汉字，有余量。

修法：在第 5 条加半句：「超时是这个估计的 3 倍，但不超过各处设计写的最长值；3 倍超过最长值时只告诉主 Agent，不来问你。」

### 3. NIT：「逐格走」的「格」页面里没有对应物

位置：「要你定的」推荐行，「再到真实项目里按它逐格走」；背景行写的是「十个阶段」。

「格」是 `journey.md` 内部对「阶段乘四行」的叫法，人在这页上没见过。背景行已经用了「阶段」。

修法：改成「按它一个阶段一个阶段走」。

### 4. NIT：草图页脚的「设计里还没写」没说是哪份设计

位置：`onepage-mockup.svg` 页脚，「额度重置后怎么知道、你回来了怎么知道，设计里还没写。」

内容属实：`journey.md` G15 第二处（怎样知道额度重置了）与 G18（攒着的汇报怎样知道人回来了）四份已放行的设计都没写。问题有两点。一是「设计」没限定，人可能读成这份用户图。二是这两件事在放行那一问的四行里没有出现，只有疑问行的第三处缺口，页面里的缺口说法分散在两处。它没有向人要任何决定，不算未决项，所以是 NIT。

修法：页脚改成「额度重置后怎么知道、你回来了怎么知道，已放行的设计里还没写，等本项目试用之后再补。」这样和「不做」一行对得上。

### 5. NIT：`journey.md` 的状态行已过期，与页面的「评审已通过」不一致

位置：`journey.md` 文首「状态：」一行，写「待第三轮复评」，并写「`onepage.md` 现在写的是 0.5，由后一步……重写」。

页面背景行写「评审已通过」。依据是 `decisions-review.json`（21:14:22，APPROVED，晚于 `journey.md` 的 20:56:12，评审的就是这一版），成立。但只看 `journey.md` 的人读到的是「待复评」。`decisions-review.json` 的 R9 已经点出这一页由后一步重写。

修法：页面放到人面前之前，由改 `journey.md` 的一步把状态行改成「第三轮决定评审（2026-10-31 21:14）APPROVED，NIT 4 条；一页稿已按新格式重写」。页面本身不用改。

### 6. NIT：第 3 条「撤下只有一条路」没提代码规则的撤下今天只覆盖一部分

位置：「对你有什么变化」第 3 条，「撤下只有一条路：对主 Agent 说一句话，或打一条命令」。

`journey.md` S7 与 G26：规则板 0.10 的 `/rules lift` 今天只管板上的条目；M3 的八条和 M7 的门改经统一安装方式之前也不在撤下范围里；这些是自举之后才办的请求。页面写成已经成立。这一页描述的是用户图 0.6 的目标样子，G26 在用户图自己的缺口表里记着，放行这一问的结论不变，所以是 NIT。

修法：第 3 条末尾加半句：「已放行的几份设计还没接上这条路，自举之后补（不做一行说的就是这个）。」或者把它并进疑问行。

## Verified Assumptions

- `decisions-review.json` verdict 为 APPROVED，模块没有停；`journey.md` 在评审之前（20:56:12 对 21:14:22）最后一次写入，评审的就是页面对照的这一版。
- 「5 处」：`journey.md` 文首 0.6 的改动里，三个决定（试运行、密钥、超时）加 ② ③ 两个回答共 5 件，与页面「对你有什么变化」的 5 条一一对应；文首第 5 项（§6.2 清单）按文中自述不是人的话，没算进去，页面也没算。
- 「11 个方向、第 6.2 节」：§6.2 正文「共 11 件」，表 11 行。
- 额度用完停住并告诉人、重置后自己接上：`journey.md` §5.2 与 §6.4 第一件，人的话「额度重置后自动接上」。
- 做完一点汇报一点：S10 与 §6.4 第二件，人的话「做完一点汇报一点，或者等收菜」，确认「都没问题」；页面三层意思（每模块一次、你不在时攒着、整个目标做完一句话带整体审查）与 S10 一致。
- 规则启用即拦、拦下按规则编号记在规则页和晨报：S7、S9、`d-code-rules-enforce`；人的原话「试运行规则啥的直接拦就行了，这样反而有问题好发现」。
- 密钥文件可读、不记谁读、密钥不进日志与提交的检查照旧：S7 与 `d-credentials-readable`。
- 超时：agent 先估、超时为估计的 3 倍、跑过后改用最近几次里最慢一次、批准时看到超时和依据、不崩、留痕、3 倍而不是估计本身是编排方裁定：S7「超时怎么定」与 `d-timeout-measured`（05:37Z 人定，08:17Z 编排方裁定）。
- 草图里的流程与 S6、S7、S10 一致：大循环放行后每个模块各放行一次、一批至多三件；第一个模块放行时开始自动推进并在对话里说一句；额度用完时由主 Agent 在对话里告诉人；主 Agent 不在 GLM 上（`journey.md` G15 第三处）。
- 页面没有改动已放行设计的措辞：「不做」一行对应 `d-freeze-until-dogfood`（§6.3 开头）。

## Unverified/Wrong Assumptions

- 一次回「都可以」同时放行三个模块：S6 与 M7 §3.9.7 允许一批至多三件，每个模块一件四行；设计没有写一句话能不能同时批三件。草图用它作示意，页面已标「示意，措辞没定」，不当作缺陷。
- 「预计 02:30 重置」这一数据在草图里出现：设计没写推进停住后怎样知道重置时刻（G15 第二处）。草图已用页脚承认，见 Finding 4。
