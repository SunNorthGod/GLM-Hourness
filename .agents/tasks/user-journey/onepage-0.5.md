# 用户图：给你看的一页

这一页按你会走的顺序，讲装上 GLM-Hourness 之后从头到尾怎么用，一共十步。
它不做新决定，只把四份已放行的设计（规则板 0.10、循环板 0.6、主 Agent 附录 0.5、派活那一块 0.6）和你定过的方向串起来，看哪里接得上、哪里还空着。
完整的在同目录的 `journey.md`（0.5，评审第 4 轮通过）。这一页只讲你会碰到的部分。

两个插件：
- GLM 通道（`dsh-glm-zcode`）：登录 GLM、发请求、看额度和高峰。
- 编排层（`dsh-hourness`）：主 Agent、项目图、两块板、晨报周报。
- 可以只装一个，装上的那组照样能用，见「只装一个时」。

## 十步

每步写你做什么、你看到什么、什么时候来问你。

### 第 1 步 装上插件

- 你做什么：在 DSH 的插件管理里装，装完重启桌面版。管理器写「已应用」只说明这一行被接受了，重启之后才算启动。
- 你看到什么：插件页各写一句从哪开始。打 `/glm-status`、`/hourness-status` 能看到每一行有没有生效，出故障的写原因。
- 什么时候问你：不问。

### 第 2 步 登录 GLM

- 你做什么：点「GLM · 上手」，点登录，在浏览器里授权（链接 5 分钟内有效）；选 GLM 的模型，发一句话试试。
- 你看到什么：对话框顶上三步，登录后打钩。没登录就发消息，先给一句中文提示，再给原来的英文报错。`/glm-status` 写现在是不是高峰、5 小时额度和每周额度用了多少、几点重置、照现在的速度什么时候用完。
- 什么时候问你：不问。

### 第 3 步 新手引导

- 你做什么：第一次打开右侧栏「项目图」，看上手页，点「去首页」。
- 你看到什么：六小块，每块最多四行。其中一块讲规则板和高峰模式：默认少做，主 Agent 不受高峰影响。上手页只自动出现一次。
- 什么时候问你：不问。

### 第 4 步 新项目，或接手已有项目

- 你做什么：在没有项目图的文件夹里发 `/wish`（可以不带话），或点卡片上的「建一张项目图」。已有项目：先听主 Agent 说它对两件事的看法（哪些验证花钱或独占机器，哪些地方不许碰），说对不对、补什么；再读它给的两件，一条拦住「不许碰」的规则和整份接管清单，各回一句「可以」。
- 你看到什么：十几秒后它说这里当成新项目还是老项目，依据是什么，判错了可以纠正。老项目里它读 README、路线、提交记录，清单里有读出来的目标、做完和没做完的事、合入前要跑的检查与每条的试跑结果；四行之后原样列出同意之后会跑的命令。仓库里的东西它一概不执行，批准之前只在临时副本里试跑逐字出自仓库已有文件的命令，不碰你的凭证。
- 什么时候问你：上面两件加整份清单，一条回复至多三件。接管来的待做活开工前要不要给你看一页放行稿，在接管项目那份设计里另问你，定之前按推荐的不看走。

### 第 5 步 许愿和访谈

- 你做什么：发 `/wish 一句话`，用自己的话回答它的问题。主 Agent 已经在别的会话时，`/wish` 会告诉你它在哪个会话，打 `/wish here` 把它移过来。
- 你看到什么：它一次问一两个开放的问题，带着自己的猜测：你想要什么，做成以后日子有什么不一样，你会怎么检查它真做成了，有什么明确不要，有什么不能改、不能花、不能冒的险。面板上目标先是虚线，每答一题多出一项。聊清楚后，给你一件四行的「确认需求」。
- 什么时候问你：聊天问「要什么、做成什么样」；只有你能定的岔路和最后的确认用四行问。你回「讲细点」「说重点」只改这一次怎么讲。

### 第 6 步 设计放行，再逐个模块放行

- 你做什么：读它交来的四行放行方案，说「可以」、补一句，或说「不行，因为……」。项目拆了模块：先放行一次框架、模块清单和你定过的方向（原文照列），再每个模块读一页放行稿，同意了这个模块才开发。没拆模块的小目标只放行一次。
- 你看到什么：设计和拆出来的任务在面板上先是虚线，你同意后变实线。拆了模块的目标，首页下面多一行各模块走到哪了，点开是「框架与模块」页，只能看。流程条写「等你批准」，意思是它在对话里等你回话。
- 什么时候问你：每次放行一件四行。每个模块的设计，先由另一个子 agent 对照你定过的方向独立审一遍，违背哪一条指出哪一条。模块没放行，它的开发一件也派不出去；放行之前，子 agent 只能读。

### 第 7 步 主 Agent 自己往下做

- 你做什么：基本不用动手。想停按暂停或打 `/goal pause`，想接着按恢复。想换高峰档位，跟它说，或打 `/rules peak 少做|不做|无影响`。想加例行的活（例如服务器巡查）或一条规矩（例如「今晚 21 点以后别推送」），跟它说：它让子 agent 写成一小段脚本，把原文给你看，你说可以才生效。
- 你看到什么：首页「现在」写谁在做哪件事，高峰时多一行「GLM 高峰中，到 18:00 · 高峰模式：少做」。对话里偶尔一行：推进开始了、额度快用完、要你回话的事。它跑会丢工作或改写历史的 git 命令之前，先存快照并告诉你恢复的命令。
- 什么时候问你：见后面的「什么时候问你」。

### 第 8 步 看面板和两块板

- 你做什么：打开右侧栏「项目图」从上往下看。「讲细点」展开，「说重点」收起，只改显示。要回话，点「需要你」里的链接跳到对话。
- 你看到什么：首页五节：效果是、需要你、现在、怎么做、上次看之后。规则板七组，循环板三组，出厂 20 项（编排层 16 项，GLM 4 项），插件带来的写「只能看」。经验页写踩过的坑和解法，页面上没有按钮，删除与恢复在对话里说。
- 什么时候问你：不问。面板只给你看，不给你操作。

### 第 9 步 收晨报和周报

- 你做什么：在主 Agent 的对话里读。嫌长说「说重点」，想细看说「讲细点」。
- 你看到什么：每天 08:30 晨报：目标走到哪、计划外的变动、卡住的、等你回话的、花费、合入前的检查和审查。每周一 09:00 周报：这周问了你几次、要你读多少、等你多久、因你的决定返工几次，测试一次通过率、审查发现和返工率。每天 02:30 夜间巡检，发现写进晨报。
- 什么时候问你：晨报不提新问题。周报可以提议：规矩该升该降，必须全审的改动清单该加，删掉 4 周没命中的规则和 4 周没跑出结果的你加的循环条目，修反复超时的脚本。四行，你同意才办；插件带来的默认条目不在此列；每周合计至多三件。

### 第 10 步 目标做完

- 你做什么：看首页「效果是」里这个目标关了没有，必要时读目标页上整体审查的批注。不满意就在对话里说，按许愿或改目标走。
- 你看到什么：目标关闭；目标页上每条「怎样算做成」对着一条证据（提交、检查日志、文件）。晨报只列没关闭的目标，关闭之后它就不在晨报里了。
- 什么时候问你：正常不问：你在访谈里定的「怎样算做成」就是依据，由独立审查逐条对照。整体审查一直不过才用四行问你。主 Agent 在对话里怎样告诉你做完了，现在没有设计写，见最后的第 ③ 件。

## 会自己发生的事

- 派活之前系统先查：缺「怎样算做完」、前面的活没做完、有等你回话的事、模块没放行、同时在做的活已满，差什么就拒绝并说明。
- 子 agent 先交计划，主 Agent 批或打回。改完文件就跑项目的检查，结果在下一步之前回给改文件的 agent。
- 交回之后派审查，深浅主 Agent 定。碰到必须全审的几类改动，系统一律按全审。
- 审查过了，主 Agent 把活做成要进主干的提交。系统核对这个提交跑过合入前的检查并全部通过，自己记下证据，才让主干往前走。合进主干之后再跑一遍完整检查。
- 子 agent 写到项目里、但出了自己工作树的文件，由派活那一块纠正，不问你。写到项目之外才问你。
- 你同意的带脚本的规则或条目，同意那一刻就生效，不试运行。代替试运行的有四样：后果事先写明；内容钉住，被改过就不跑，等你再同意；命中次数、耗时和失败看得见；你一句话或一条命令就能撤。写在代码里的新规则仍先试运行。
- 拦路脚本超过 10 秒没回话，先按条目写明的办法判：缺省放行，主干前进之前缺省拦下。脚本在后台接着跑至多 10 分钟，晚到的拦下当场告诉主 Agent，由它改或回退。
- 连续 3 个目标轮图和派活都没有变化，系统停住推进、记复盘，主 Agent 在对话里说明；被高峰挡着的轮不算。
- 每一个数（派活、问了你几次、返工、检查）由系统自己记，模型报的不算。
- 放在哪：规则、开关、高峰档位、你加的循环条目和你同意过的脚本放在仓库的 `docs/rules/`、`docs/loops/`，随 git 走。在等的工作、命中计数、违规记录、运行记录、经验放在项目的 `.llm/`，不进 git。用户目录只留 GLM 登录信息、ZCode 设备号、人设、关于你的记忆、整个账号的额度与用量、DSH 配置里的插件配置。换电脑或新克隆之后，规则与条目照仓库里的文件读回来；带脚本的只有图上有你看过原文、拍过板的记录才跑，没有的列出来等你再同意。

## 什么时候问你

- 只问五类必须你定的事：改目标、「怎样算做成」或不做什么；仓库以外的动作；收不回或对外的动作；新增运行时依赖或升大版本；以后改起来很贵的方向。其余主 Agent 自己定、留痕，你可以推翻。
- 问的方式只有三种：聊天（要什么、做成什么样）；四行（一件事一个方案，题目下面背景、推荐、疑问、不做各一段，一条回复至多三件）；不问（只告诉你，或什么都不说）。
- 开发中碰到的问题分三档。只影响一个模块、能撤回的，主 Agent 自己定，下一批里告诉你。要改某个模块的设计方向的，这个模块退回设计，你重新看一页放行稿。要改整个框架的，要你说话，主 Agent 带你的原话把目标退回设计，受影响的活先停。判不准往高一档放，已经进主干的活不动。
- 审查或合入前的检查一再不过、同一件活第三次返工之前，系统停下，主 Agent 把事实和一份四行草稿攒进下一批问你。
- 写项目之外的文件：四行放在主 Agent 回复的末尾，你的下一条消息回「可以」才放行；只放行同一个调用一次，30 分钟内有效。
- 有事等你超过 24 小时，再说一次。
- 不问：子 agent 的问题由主 Agent 答；高峰里没别的活可做时也不问。

## 会碰到的几种情况

- GLM 登录过期：主 Agent 跑在别的模型上时，它在下一次回话里告诉你打 `/glm-login`。主 Agent 自己跑在 GLM 上时它也回不了话，你在 DSH 里直接看到请求失败。`/glm-status` 第一行写登录失效。
- 额度快用完：用到 80%，或照现在的速度一小时内会用完，主 Agent 在下一次回话里说一句，每个额度周期只说一次。插件不替你换模型或套餐。额度真的用完时自动推进怎么办，现在没有设计写，见第 ② 件。
- 高峰（工作日 14:00–18:00，GLM 全价，其余半价），默认少做：同时至多 1 个 GLM 子 agent，练习题、对照实验、大的评审挪到 18 点以后，必要的活照做。不做：GLM 子 agent 的操作、主 Agent 派 GLM 子 agent 的那一次、自报花 GLM 积分的脚本都排队，18 点以后系统恢复并叫原来的 agent 接着做。主 Agent 任何一档都照常回话、和你商量。想让一张排着的单这次高峰照常做，打排队文字里给的 `/rules let <单号>`，档位不变。
- 高峰里只剩挪到 18 点以后的活：自动推进先停着，不来问你。18:00 循环板先把推进接上，再叫醒主 Agent。
- 崩溃或重启：一般不用管，重启后自动接着走。你自己按的暂停不替你恢复；关桌面版前 30 秒内发生的暂停算关机带来的，重启后恢复。主 Agent 的会话被归档或找不到时，首页写「在一个会话里打 /wish here」。仓库里的规则文件被规则板以外改过，或存档里有不是规则板写的记录，规则页列出来、不生效，等你打 `/rules recovery <编号> 照改` 或 `忽略`。
- 方案被否：主 Agent 按理由换一个方案再提，这件事一直在「需要你」里，直到有一版你同意。
- 放行之后才发现不对：只改某个模块的设计方向，主 Agent 把这个模块退回设计，你重新看一页。改到整个框架，你说一句，它带你的原话把目标退回设计。已经进主干的活不动，要不要重做是新设计的事。
- 审查一再不过：第 1、2 轮自动修、自动再审，第 2 轮还不过自动加第 3 轮；必须改的条数没减少，或第 3 轮还不过，这件活停下不再派，直到你回话。

## 只装一个时

- 只装 GLM 通道：只有第 1、2 步，之后是普通的 DSH 对话。没有项目图、主 Agent、两块板、晨报周报和高峰模式。高峰时 GLM 会话照旧收到一句计价提醒，原文和今天一样。额度快用完、登录失效这两件没有主 Agent 来说，你不打 `/glm-status` 就不知道，这一格现在空着。
- 只装编排层：没有第 2 步。高峰模式不起作用，页上写明；循环板少两项（高峰开始、高峰结束），其余 14 项照常；用量按 token 列，没有额度和高峰行。主 Agent 可以跑在任何模型上，提醒只说「用强一点的模型」，不点名。

## 替你定了的方向

- 格子之间对不上、与你定的方向相反、或者谁都没写的，一律写成缺口，不替设计拿主意。没选直接补一个说法：那会变成没人评审过的新决定。
- 已放行的设计不改。要它们改的，记成给对应模块的请求，等自举之后再办。没选现在就改：在做的实现不接新请求。
- 几处分工是编排方裁定的，你可以推翻：发给模型的高峰提醒原文归 GLM 通道，档位和少做的上限数归规则板，高峰结束时叫醒主 Agent 归循环板，周报提议删久不用的规则和条目。
- 方向清单在 `journey.md` 第 7 节，共 35 条，每份设计对照它，违背即挡路。这一轮补进去的有：主 Agent 不受高峰影响；带脚本的规则或条目即刻生效、拦路脚本超时先放行；属于项目的都放在项目里，用户目录只留登录信息和关于你的记忆这类；两层循环也用在你的项目里。

## 还空着的格子

这些是各模块之间对不上、或者谁都没写的格子。已放行的设计现在不改，等自举之后再办。

- 没有项目图时第一步打什么：接管项目那份设计说 `/wish` 先调接管；主 Agent 那一块说这时 `/wish` 报「还没有项目图」；面板上的卡片写 `/hourness-init`。请主 Agent 那一块接上接管，面板改指 `/wish`。在那之前，接管设计写了过渡的办法。
- 每个模块放行前的独立设计审查：派活那一块写了审查记录的形状，主 Agent 那一块的模块放行检查还没有数这条记录。在它加上之前，放行页能在没有审查的情况下提出来，只靠主 Agent 自己对照，并在放行稿里写出来给你看。
- 主 Agent 是哪个会话的记录：今天放在用户目录，按你的规矩该进项目的 `.llm/`，留给主 Agent 那一块的对齐。面板和循环板只经它导出的函数读，搬家前后都成立。
- 周报里的比率：派活那一块让周报把通过率、返工率这些比率经主 Agent 的对话给你；指标流水那份设计按项目宪章只给命令行和面板，不进主 Agent 的对话。这一件在指标流水那份设计里单独问你，你答了再改派活那一块。
- 只装 GLM 时没人告诉你额度快用完、登录失效：GLM 通道那一块定要不要让输入框下方的 GLM 按钮显示这两件。登录过期时请求失败的报错是不是人话，也由它补。
- 申报写项目之外的文件时，「人说可以」由环境与检查那一块自己认，不走主 Agent 那一块的记录。两处认法并存，环境与检查那一块要么写明为什么，要么改走。

## 放行

① 放行用户图 0.5

背景：这张图把四份已放行的设计和你定的方向，按你走的顺序**串了一遍**。

推荐：评审已过，**定稿**后改成 `docs/USER-JOURNEY.md`，自举和真实项目试用按它逐格走。

疑问：最没把握的是**两格还空着**，见下面的第 ② ③ 件。

不做：不为这两格现在去改**已放行的设计**，等自举之后再提。

② 额度用完时自动推进怎么办

背景：GLM 额度用完后请求会一再被**服务端拒绝**，已放行的设计没写自动推进该怎么办。

推荐：推进**停住并在对话里告诉你**，额度重置后再接着走。

疑问：最没把握的是**重置后要不要自动接上**，还是等你说一声。

不做：不**自动换模型或套餐**，项目宪章说过不替你做这个主。

③ 目标做完时怎样告诉你

背景：目标做完后，系统只在图上把它**标成完成**，没有设计写主 Agent 怎样告诉你。

推荐：主 Agent 在对话里用**一句话**说做完了，带上整体审查的结论。

疑问：最没把握的是**要不要把每条证据都列出来**，还是只给结论。

不做：不让**晨报**来告诉你，晨报只列没关闭的目标。

这三件按推荐定，可以吗？
