# 补拦截、补检查：给你看的一页（设计 0.6）

## 你会看到什么

一个 agent 要把新曲目写进音乐软件在工作区外的歌单文件。系统先拦下它，让它在回复末尾放一段申请：一行题目写明是哪个文件，再加背景、推荐、疑问、不做各一行，最后问「放行这一次，可以吗？」。文件在不在、多大、改前会不会先备份，都是系统查了写的；agent 只用引号写它的目的和试过的别的办法。你回一句「可以」，这一次放行；回别的都不放。

## 对你有什么变化

1. agent 要写工作区外的文件时向你申请，你回「可以」才放行这一次，30 分钟内有效，重启就作废；你 2 小时不回，申请自动撤销。
2. 写在代码里的规则从启用那天起就拦，不再先试运行一阵。每次拦下都记下规则和经过，晨报和规则板看得到；拦错了你一句话就能撤下某条规则（对主 Agent 说，或打 /rules lift）。读登录密钥文件不拦。
3. agent 改完文件，下一步开头多一小段检查结果：每个检查几处问题，至多 5 条带文件和行号，没问题就不出声。每个会话开头告诉 agent 项目里有哪些工具、改哪些文件会跑检查、临时脚本放哪。
4. 同一件活要修第 3 次时，主 Agent 在下一批问你「先停下查原因，可以吗？」。
5. 晨报多几行：拦了几次、拦下之后走对几次、申请放行几次、代码里跳过检查的注释有多少处。
