## 发现

### 挡路

没有。合入的这一版在 git 项目里把列表、页面、主 Agent 一行、投递、到点任务、删除恢复、重启事件与最近跑过的都走通了。

### 不挡路

1. `l4-glm` 工作区的循环板说「还没有主 Agent」，可这个会话就是主 Agent。原因是两套行对「项目」的认法不一致。`l4-glm` 不是 git 仓库，循环行按 git 根把它的会话认成 `GLM-Hourness` 项目，再到 `GLM-Hourness/docs/graph` 找主 Agent 记录，找不到。图行与 `/wish` 按会话的工作目录取图目录，记录写在 `.llm/l4-glm/docs/graph` 名下（`7cc3e87f167358a7.json`）。这样一来，在 `l4-glm` 会话里打 `/loops` 或打开这个会话，都会让桌面版跑本仓库主检出的循环板，并写主检出的 `.llm/loops/`。项目根就是工作区根的项目不受影响（临时项目里全部走通）。要编排方定以哪种认法为准；在那之前，标准的 L4 工作区 `l4-glm` 验不了循环板的投递。
2. 工作树里跑探针时，场景目录本身不是 git 仓库，循环行会把它认到主检出的项目上，于是改写主检出的 `.llm/loops/view.json`。本次见到两回：20:42:07 与 21:19:58，都是 634 字节、只有两项、没有 `waiting`、`recent`、`peak`、`holder` 的旧格式文件。时刻分别对上 `.worktrees/ug`（20:34–20:42）与 `.worktrees/m3`（21:12–21:19）的探针运行，这两个分支当时都不含 Batch 3。`GLM-Hourness` 会话的循环板页面因此写「循环板的 view.json 读不懂，下面是上一次读到的样子」；20:45:22 桌面版重写之后，页面自己恢复了。这种文件没让本次合入出错，但说明探针的场景没有和主检出隔开：一个含 Batch 3 的探针进程同样能拿主检出的运行锁，按主检出 `docs/loops/` 里的条目运行。眼下主检出没有人的条目，所以还没有影响。在本仓库的循环板上加会跑东西的条目之前，要先让探针场景各自是 git 仓库，或者把探针运行目录挪到仓库外面。
3. `loops.host-restarted` 的 `downMinutes`（字段名「停机的分钟数」）算的是这次开始跑项目距上次开始跑项目多久，不是停了多久。本次只停了约 1 分钟，值是 30（上次 22:35:35 开始跑）。用 `downMinutes atLeast N` 筛选的条目会被误触发。`src/loops/run.ts` 的 `restarted()` 用的是 `previous.startedAt`；要得到停机时长，需要一个上次停下的时刻（干净退出时写在 `host` 里，或者用锁最后一次刷新的时刻）。
4. Batch 3 给 `view.json` 加了必有的字段（`waiting`、`recent`），版本号仍是 1。所以旧一版写出的 `version: 1` 文件，新页面一律读不懂（第 2 条就是这样暴露的）。另外第一次读就读不懂时，页面除了那一句，下面还写「还没有你加的」，好像知道里面没有人的条目一样。
5. 「什么时候」不写筛选：两项高峰条目都写「碰到「GLM 高峰开始或结束」」，实际上一项只在开始时跑，另一项只在结束时跑。
6. 事件还没有谁声明时，「什么时候」和灰显的原因直接写事件 id（「碰到「hourness.trunk-advanced」或「hourness.outside-advance」」）。设计 §8.5 要求 id 只作小字。M7 合入后这两个事件有了标题，这里就会好；在那之前页面上是两个英文 id。
7. 主 Agent 一行写的是「主 Agent 收得到这块板的消息 · session-1e8476c6-…」：直接给会话 id，点不开。设计 §8.2 第 1 条写的是「主 Agent 在会话「<标题>」」，点开跳到那个会话。没有主 Agent 时这一行少了后半句「，到点的几项才会开始」。
8. 行健康写「循环板自己的 5 项条目已登记」，这个数是登记表的全部条目，包含图行交来的 `graph.third-rework`。插件页的说明「另带四项自己的条目」是对的，行健康这一句的「自己的」用错了。另有一处小的：「要改：跟主 Agent 说「把README 变了就告诉主 Agent改成……」」，名字和「改成」直接连在一起。
9. 记一笔已写明的解释，不是新缺陷：按 §18.7，只告诉主 Agent 的条目从仓库文件直接认回，不看这台电脑上有没有人同意过（实施计划 Interpretations 1、2），本次就是这样加进条目的。所以合进来的一个提交只要带一份这样的条目文件，就能把一段话送进主 Agent 的上下文，`wake: true` 时还会叫醒它。设计第 33 条 (b) 的写法是不跑。
