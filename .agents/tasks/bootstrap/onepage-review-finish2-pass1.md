# 一页稿评审：bootstrap（接管项目）onepage.md 与 onepage-mockup.svg

评审对象：`.agents/tasks/bootstrap/onepage.md`、`onepage-mockup.svg`，对照 `design.md`（0.6，含复核第 1 至 3 轮修订）。第一遍（`onepage-gate-finish2.json` 评审前不存在）。

结论：CHANGES_REQUESTED。MEDIUM 3 条（P1、P2、P3），NIT 5 条（P4 至 P8）。

字数：onepage.md 共 1,335 个汉字（U+4E00 至 U+9FFF，整个文件，含 17 个标题字与 19 个图片替代文字；不含 SVG）。分段：标题 17，一次接管 193，对你有什么变化 611，要你定的 423，替你定的方向 91。上限 1,500，通过。与作者报的 1,335 一致。

## 发现

### P1　MEDIUM　页面与草图展示的问话形状，设计里没有；人批准 D1 的 41 条会把旧形状钉进项目图

位置：`onepage-mockup.svg` 全图与 `onepage.md` 的「要你定的」；对照 `design.md` §0.1（「每件是一个题目加四行：背景、推荐、疑问、不做」）、§1.4（`bootstrap-paths` 第 5、8 条，`bootstrap-review` 第 2、3 条，`bootstrap` 特性一行的 L4「对话里每件事都是题目加四行」）、§5.4、§5.9、§7.3（`listLines` 的四行模板，「每个模板恰好一处加粗」）、§18（D1 至 D3 的四行）。

问题：草图画的是一句是非问（推荐和理由在句子里，真有代价才多一句），页面「要你定的」同样用这个形状。设计要造出来的是题目加四行带加粗。人读页面、放行之后，实现按设计走，人看到的是另一种样子。更直接的一处：页面 ① 请人同意「41 条照原样写进项目图」，这 41 条里至少有五条（`bootstrap-paths` 第 5、8 条，`bootstrap-review` 第 2、3 条，特性一行）的内容就是「题目加四行」「每行过 `proposalLineRefusal`」，同意即把旧形状写进怎样算做完。页面和草图展示的东西与人被请求批准的东西互相矛盾。作者报告已承认设计的这几节没改，留给下一步；一页稿要和设计一致，这一步不能留。

修法（同一遍内，只改文字）：
1. `design.md` §0.1、§5.4、§5.9、§7.3（`listLines`、`questionsDraft` 的模板）、§18 改成 `d-ask-three-gates` 的形状：每件一句是非问，建议与理由在句子里，有真代价才加一句；图上的记录字段（问了什么、建议、理由、代价、没走的路、人的原话）不变，只改给人读的文字。§18 的三件改成与页面 ①②③ 同形。
2. §1.4 里凡写「题目加四行」「四行」「每行恰好一处加粗」的验收（`bootstrap-paths` 第 5、8 条，`bootstrap-review` 第 2、3 条，`bootstrap` 特性一行）改成对应的新说法（例如「每件是一句是非问，含建议与理由；有代价时多一句；一条消息至多三件；过 `plainWordsIn`」），M3 的 `proposalLineRefusal` 一类按 M3 附录实际的新规则写，不确定的写成对 M3 的请求并注明。
3. 重数 §1.4 的条数与验收一列字数（口径同 §19 第 1 条：去掉反引号和首尾空白，UTF-16 长度），§18 与 §19 第 1 条的数随之改；页面 ① 的「41 条」「六千多字」随之核对。
4. 若编排方裁定「问话形状归 M3 的一处模板，接管只引用」，则 §7.3 第一段已有的话（「格式再变，只动 M3 的那一处与这里的模板」）要落成一句明确的裁定，并在 §17 加一行；页面仍要和设计写的一致。

### P2　MEDIUM　变化第 4 条首句「命令在你同意之前一条都不跑」与同一条后文相反，也不是设计的边界

位置：`onepage.md` 「对你有什么变化」第 4 条。对照 `design.md` §6.1 表第 1 行、§8.5、§0.1「主 Agent 从文档里读出来的命令，你同意之前一条都不跑」。

问题：第 4 条首句说命令同意前一条都不跑，接着说「读出的命令先在系统临时目录的一份副本里试跑」，同一条里自相矛盾。设计的边界是：主 Agent 从文档里读出的命令不跑；逐字写在仓库已跟踪文件里或默认表里的命令，会在批准前于隔离副本里试跑（项目自己的构建脚本、`conftest.py` 之类会真的执行）。页面把两类合成一句「读出的命令」，读者会以为批准前没有任何项目代码在本机执行。

修法：把首句与第二句改为：「主 Agent 从文档里读出来的命令，你同意之前一条都不跑。项目文件里原样写着的命令，会先在系统临时目录的一份副本里试跑：不带你的密码和令牌，推送不出去，每条最多 10 分钟，合计最多 45 分钟，用完即删。」其后 Windows 的一句保持。

### P3　MEDIUM　「55 个方向」的数在设计内部对不上，页面只补了一个

位置：`onepage.md` 「替你定的方向」；对照 `design.md` §0.1「替你定了的方向性的事（都可以推翻，§17）」与 §17。

核对：§17 共 55 行（脚本数得），第 13 行（读项目门禁的模式）记的是人自己的决定，扣掉得 54，与页面一致；第 14、16 行是编排方的裁定，与页面「2 条」一致。但 §0.1 同一标题下的条目里，不在 §17 的有两条：「接管不写方向清单」（页面已补）与「接管不碰你电脑上跨项目的东西」（§2.5 存放表末行，§17 无此行）。页面说「另 1 个……只写在第 0.1 节」，漏了第二个，而且作者没有说明排除它的依据。此外 §17 第 49 行「工具节点的检查行」的取舍（接管不向循环板提检查条目）直接来自设计上下文里编排方的「Check entries seam」裁定，页面的「含 2 条编排方的裁定」没有计入也没有说明。要求是「把每个这样的方向都数上，接缝裁定也算」。

修法（二选一，写明依据）：
- 把第二个 §0.1 独有的方向也计入：「替你定了 56 个方向……另 2 个（接管不替你写方向清单；接管不碰你电脑上跨项目的东西）只写在第 0.1 节」；编排方裁定改为 3 条并列出第三条（检查条目不进循环板），或在 `design.md` §17 补上这两个独有项与第 49 行的出处，使 §0.1 的「§17」说法成立，页面据此写「N 个全列在第 17 节」。
- 若作者认为「跨项目」是人已定的 `d-memory-scope` 的直接落地、不算替人定的方向，则 §0.1 把它从「替你定了的方向性的事」里移出，另放一处，页面保持 55。

### P4　NIT　草图的「同意之后会跑的命令」与它旁边的「旧告警不挡合入」不一致

位置：`onepage-mockup.svg` 右栏命令清单（第一行 `uv run ruff check .`，类为合入前）与注意事项末二句。对照 `design.md` §5.6 第 3 步、§7.3「本版有 `changed` 行时加『旧告警不挡合入，只挡新出的』」。

问题：注意事项里有旧告警一句，说明门禁里有 `changed` 行；按 §5.6，HEAD 上红的检查器在门禁里写成 `changed <格式> $ <命令>`，清单里该行的命令应是带 `{files}` 的那一条，而草图第一行是整项目跑的 `uv run ruff check .`，没有带 `{files}` 的合入前行。

修法：把草图第一行改为 `uv run ruff check --output-format concise {files}`（类仍为合入前，写法同第 (二) 种「试跑约 N 秒；超时 30 分（默认）」），保留第三行改完文件就跑的同一命令；或删去注意事项里旧告警一句。

### P5　NIT　D1 没告诉人怎样看那 41 条

位置：`onepage.md` 要你定的 ①。对照 `design.md` §18 末段（「人对 D1 说『讲细点』时，编排方逐件读 §1.4」）。

问题：人被请求对一份自己没读过的清单说「可以」，页面没给他看的办法。成本一句只写了试跑那件没把握。

修法：理由句里加半句：「想看哪一件，说一声，我念给你」。

### P6　NIT　①②③ 里「可以吗」在建议之前，和草图及形状 (a) 的顺序不同

位置：`onepage.md` 要你定的 ①②③。

问题：形状 (a) 要求问句里含建议与理由，「可以」接的是刚读到的那句；页面先问「……，可以吗？」再写「我建议……，因为……」，建议在问句之外，且与问句内容重复。草图是先建议后「可以吗？」。

修法：把 ① 改为「……我建议照原样写进项目图，因为逐条念要六千多字，读着累，不合适的地方做到那一件时再改，可以吗？代价是……」；②③ 同样调序。

### P7　NIT　「替你定的方向」一段超过一句，带记账式括号

位置：`onepage.md` 「替你定的方向」。

问题：要求是一行写数目与所在章节。现在三句，含「该节共 55 行，其中 1 行记的是你自己定的，没算」这类人不需要的核对细节。

修法：P3 定下数目后压成一行，例如：「替你定了 N 个方向，每个都能推翻，列在 design.md 第 17 节和第 0.1 节；其中 3 条是编排方的裁定。」核对细节留在评审文件或设计的修订记录里。

### P8　NIT　变化第 4 条只写了试跑副本挡住了什么，没写没挡什么

位置：`onepage.md` 「对你有什么变化」第 4 条。对照 `design.md` §6.2 第 6 点（网络不限）、§6.5 第一行。

问题：副本能上网；测试若调用不要凭证的外部接口，设计承认挡不住，事后只能从日志查。页面只列了保护（不带密码令牌、推送不出去）。

修法：补半句：「副本能上网，测试若去调外部接口挡不住，事后从日志查」。
